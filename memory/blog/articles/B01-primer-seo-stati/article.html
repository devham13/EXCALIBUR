Текст набит ключами, а человек уходит после первого экрана - страница не работает ни в обычной выдаче, ни в нейроответах. SEO-статья в 2026 году - это полный ответ на запрос, написанный нормальным языком и разложенный на блоки, которые можно процитировать. Ниже один pipeline: семантика, каркас, черновик, мета, FAQ, schema и финальный чеклист. Пройдя его, вы соберете seo текст для блога без второго проекта под geo оптимизацию статьи.

Не делайте два текста "для робота" и "для людей" - один longread должен читаться с экрана и отдавать фрагменты нейропоиску без соседних абзацев.

Объедините SEO и GEO в одной статье

SEO-статья - текст, который закрывает конкретный запрос и помогает человеку не вернуться в поиск сразу после клика. GEO не заменяет SEO: без индексации, нормальной структуры и честных фактов AI просто не увидит вашу страницу. GEO дополняет SEO: вы упаковываете уже полезный материал так, чтобы нейросеть могла процитировать определение, шаг или ответ из FAQ.

Поисковики смотрят на смысл, а не на плотность ключей - переспам вредит. Нейросети вырезают короткие фрагменты: каждый H2 должен быть понятен без контекста (island test). Первые 2-3 предложения секции - мини-ответ, без "разогрева".

Соберите семантику и разберите выдачу

Начните с primary query: для этой темы это "как писать seo статьи". Зафиксируйте интент (how-to, сравнение, чеклист) - от него зависит глубина и формат. Семантику собирают в Яндекс Вордстат и Яндекс Вебмастер: основной запрос, уточняющие формулировки, тематические слова из подсказок.

Secondary queries ("seo текст для блога", "geo оптимизация статьи") - в подзаголовки и абзацы, без абзаца из ключей подряд. Разберите 5-7 URL из ТОП: нет чеклиста, таблицы, сильного lead или GEO - ваш угол. Один primary query на страницу; вторичные только там, где раскрывают подвопрос.

Создайте каркас longread и напишите черновик

Универсального объема SEO-статьи не существует - он зависит от темы и конкуренции в выдаче. Для how-to longread в нашем блоге рабочий коридор 8 500-9 500 знаков текста: достаточно глубины без простыни. Title влияет на клик в выдаче; ориентир около 55-60 символов с ключом и триггером (гайд, чеклист). H1 на странице не дублируйте с Title дословно: Title продает клик, H1 задает обещание на странице. H1 - один на страницу; H2 и H3 - смысловые блоки, не склад ключей.

Lead-абзац - 350-500 знаков: боль, суть ответа, что получит читатель. Без формулы "в этой статье вы узнаете". Абзацы в теле - ориентир 3-5 строк; списки - для перечислений и шагов. Типичная ошибка: писать seo текст для блога потоком ключей. Лучше короткий подзаголовок и один четкий абзац, чем три абзаца без структуры.

  1. Зафиксируйте интент. How-to, сравнение или чеклист задают число H2 и нужность таблицы.
  2. Соберите семантику. Primary query - в lead и 1-2 H2; secondary - там, где раскрываете подтему.
  3. Нарисуйте outline. Каждый H2 = один подвопрос; первое предложение секции = тезис для GEO.
  4. Напишите lead. Прямой ответ в первых 2-3 предложениях, без "разогрева".
  5. Разложите черновик по блокам. Короткие абзацы, пример "плохо/хорошо" для lead, таблица если сравниваете SEO и GEO.
  6. Добавьте FAQ и мета. Пять-семь вопросов с ответами 2-4 предложения; Title и Description до выкладки.

Каждый H2 - самодостаточный "остров": вырежьте блок, смысл должен остаться. E-E-A-T - автор, дата, ссылки на первоисточники; не выдумывайте проценты без URL.

Настройте мета, FAQ и schema

Description - ориентир до 150-160 символов: обещание результата и primary query без кликбейта. Блок "Частые вопросы" в HTML - не декор: вопросы совпадают с реальными формулировками (сколько символов, что такое geo, нужна ли schema). Ответы короткие - готовые чанки для AI и расширенных сниппетов.

Для блога базовый набор schema - BlogPosting (или Article) плюс FAQPage в JSON-LD. Разметка живет в meta или отдельном schema.jsonld, не дублируйте простыню JSON в body. Текст в FAQ и в JSON-LD должен совпадать; расхождение бьет по доверию к разметке. Alt у картинок описывает сцену, не "seo картинка ключ".

Заведите шаблон: research-notes, article.html, meta, schema, cover - один pipeline на тему. Чеклист по всему сайту под нейропоиск - в гайде по GEO-оптимизации. Связать контент с автоматизацией поможет курс по Make.com (офер - не больше двух упоминаний).

Пройдите чеклист перед публикацией

Перед выкладкой пройдите список - можно сохранить как шаблон в таблице или Notion. Делайте финальный прогон вслух: где спотыкаетесь, сокращайте.

  • Primary query закрыт в lead и H2; secondary без переспама
  • Title около 55-60 символов, отличается от H1; Description с обещанием
  • Один H1 на странице (в теме WP), в body только H2 и H3
  • Каждый H2: тезис в первом предложении, island test пройден
  • Абзацы 3-5 строк; списки и таблица, где уместно
  • FAQ 5-7 пар; ответы фактурные, не пересказ всей статьи
  • Schema BlogPosting + FAQPage; datePublished и dateModified актуальны
  • Внутренние ссылки 2-3: главная блога, релевантные landing
  • Внешние ссылки на первоисточники (гайд Яндекса по SEO-тексту, Вордстат)
  • Нет выдуманной статистики и штампов из редакционного контракта
  • llms.txt и robots.txt: AI-краулеры не закрыты случайно
  • CTA не больше трех упоминаний офера на статью
  • Читабельность: нет "кирпичей" без подзаголовков
  • Обложка с понятным alt; inline-картинки только с описанием сцены

Частые вопросы

Сколько символов должно быть в SEO-статье?

Универсальной нормы нет - объем зависит от темы и конкурентов в выдаче. Ориентир для how-to longread: 8 500-9 500 знаков, если SERP требует глубины. Сокращайте, если блок не проходит island test; не раздувайте текст без новых фактов.

Что такое GEO в SEO?

GEO (Generative Engine Optimization) дополняет SEO: цель - цитирование в AI-ответах при сохранении индексируемой базы. Начните с нормального SEO-текста, затем добавьте answer-first блоки, FAQ и schema. GEO без индексации не работает.

Нужно ли переспамить ключевые слова в 2026 году?

Нет. Используйте primary query в заголовках и lead, secondary и LSI - естественно в H2 и абзацах. Если абзац звучит как список ключей - перепишите его под вопрос читателя.

Чем Title отличается от H1?

Title - для сниппета в выдаче (ключ и триггер, около 55-60 символов). H1 - заголовок на странице. Не дублируйте дословно: разные роли, один интент.

Какие schema нужны для SEO-статьи блога?

Минимум BlogPosting (или Article) и FAQPage, если есть блок вопросов. JSON-LD в отдельном файле; текст FAQ совпадает с видимым HTML.

Что такое llms.txt и нужен ли он блогу?

llms.txt - файл-подсказка для AI-краулеров. Полезное дополнение к sitemap, не замена индексации. Заведите на сайте, когда блог становится регулярным каналом.

Как проверить статью перед публикацией?

Пройдите чеклист из раздела выше: семантика, мета, H2-чанки, FAQ, schema, ссылки, читабельность. Затем технический QA: linter HTML, проверка ссылок, slop и каннибализация ключей по скриптам Excalibur.
