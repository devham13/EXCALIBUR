Вы собрали ключи из Wordstat, а текст читают только роботы: люди закрывают страницу после второго абзаца. SEO-статья в 2026 году - это не полотно с пятнадцатью вхождениями, а longread, который закрывает запрос и удерживает внимание. Ниже - единый workflow: интент, семантика, структура, черновик для людей, мета, FAQ, schema и GEO-слой для нейропоиска. После гайда вы напишете seo текст для блога по чеклисту из пятнадцати пунктов и не будете делить SEO и GEO на два отдельных проекта.

TL;DR / Быстрый инсайт: SEO-статья закрывает конкретный запрос человека; GEO дополняет SEO, чтобы фрагменты попадали в AI-ответы (Яндекс Нейро, Google AI Overviews). Универсального объёма нет - ориентир how-to longread: 8 500-9 500 знаков. Порядок работы: интент → семантика → outline H2 → lead → черновик → мета → FAQ → schema JSON-LD → чеклист. Переспам ключей вреден; каждый H2 - самостоятельный "остров смысла" с ответом в первых предложениях.

Классическое SEO отвечает: найдёт ли человек страницу и кликнет ли в сниппет. Нейропоиск вырезает фрагмент из текста, а не показывает страницу целиком. RAG - когда ИИ сначала находит куски на сайтах, как библиотекарь с карточками, и собирает ответ. Один материал должен быть и читаемым, и "вырезаемым".

Эта страница - эталон формата B: шаги, чеклист, FAQ. Один контракт вместо "сначала SEO, потом GEO".

Объедините SEO и GEO в одном материале

SEO и GEO - не два проекта, а два слоя одного контента. SEO даёт индексацию, сниппет и удержание на странице. GEO (Generative Engine Optimization) - оптимизация под цитирование в генеративных ответах, когда пользователь спрашивает нейросеть, а не вводит запрос в строку. GEO без SEO не работает: если страница не в индексе и без структуры, AI её не увидит.

Поисковики оценивают смысл, а не плотность ключей - переспам вреден. Google подтверждает: SEO best practices актуальны для generative AI; отдельных "GEO-хаков" вместо people-first контента не требуется. llms.txt полезен AI-краулерам, но Google Search не использует его для ранжирования.

Формат ответа Сниппет Title + Description Короткий фрагмент из H2 или FAQ

Делайте: пишите для человека, упаковывайте для машины - snippet-first в начале секций. Не делайте: отдельный "роботский" текст под AI - он хуже и для людей, и для цитирования.

Запрос и интент → семантика (Wordstat) → outline H2/H3 → lead-абзац → черновик для людей → мета Title/Description → FAQ → schema JSON-LD → чеклист перед публикацией

Пройдите workflow: от интента до черновика

Ниже - девять шагов, которые закрывают запрос "как писать seo статьи" без воды. Каждый шаг - действие, не теория.

  1. Шаг 1: Определите интент. Откройте SERP по primary query "как писать seo статьи", зафиксируйте тип страниц (how-to) и обязательные подтемы конкурентов.
  2. Шаг 2: Соберите семантику. Primary + secondary из карточки темы; кластеры в Яндекс Вордстат и Яндекс Вебмастер; сгруппируйте 3-5 смысловых блоков под H2.
  3. Шаг 3: Разберите ТОП-5. Выпишите повторяющиеся H2 и пробелы (читабельность, GEO, чеклист) - ваш дифференциатор.
  4. Шаг 4: Составьте каркас до текста. H1 - один на страницу; 4-6 H2; H3 для деталей; lead 40-70 слов с прямым ответом.
  5. Шаг 5: Напишите черновик для людей. Короткие абзацы 3-5 строк, списки, таблица "ошибка → что делать"; без переспама ключей.
  6. Шаг 6: Добавьте SEO-слой. Title около 60 знаков, Description 140-160, ключи в H1, первом абзаце и 1-2 H2 естественно; alt у изображений по содержанию.
  7. Шаг 7: Добавьте GEO-слой. Snippet-first в начале каждого H2; FAQ 5-7; llms.txt - опционально, не миф "обязателен для Google".
  8. Шаг 8: Подготовьте schema. BlogPosting + FAQPage в JSON-LD; даты datePublished / dateModified актуальны; текст FAQ совпадает с HTML.
  9. Шаг 9: Пройдите чеклист 15+ пунктов (семантика, мета, структура, ссылки, island test, mobile) перед publish.

Делайте: "главный ответ → детали" в каждой секции. Не делайте: seo текст для блога как поток ключей.

Постройте структуру longread: H1-H3, lead, списки

Универсального объёма нет - зависит от темы и конкуренции. Длина сама по себе не влияет на ранжирование. Для how-to longread ориентир 8 500-9 500 знаков.

Title (~60-65 знаков) и Description влияют на сниппет. H1 - на странице, Title - в выдаче; не дублируйте. H1 один; H2-H4 делят блоки. Абзацы 3-5 строк, списки для перечислений.

Ошибка Как проверить Что делать
Переспам ключей Прочитайте вслух - звучит как реклама? Оставьте primary в H1 и lead, secondary - в 1-2 H2
Длинные "кирпичи" Абзац больше 6 строк? Разбейте на 2 абзаца или список
H2 без ответа Вырежьте блок - смысл понятен? Добавьте тезис в первое предложение секции

Делайте: island test - каждый H2 самодостаточен для AI-извлечения. Не делайте: раздувать текст до 15 000 знаков без новых фактов - AI и люди ищут конкретику.

Добавьте FAQ и schema: BlogPosting + FAQPage

FAQ в HTML - готовые чанки для AI. Schema.org - подсказки для поисковиков; JSON-LD в отдельном файле. Минимум: BlogPosting + FAQPage; текст FAQ совпадает с HTML. Site-wide GEO - в материале geo оптимизация сайта.

Делайте: FAQ 5-7 пар. Не делайте: FAQ в schema без HTML на странице.

Пройдите чеклист перед публикацией (15 пунктов)

  • Primary query закрыт в lead и H2; secondary вписаны без переспама
  • Title около 60-65 знаков, отличается от H1; Description с обещанием и ключом
  • Один H1 на странице (в теме WP), в body только H2/H3
  • Каждый H2: тезис в первом предложении, блок понятен без контекста
  • Абзацы 3-5 строк; списки и таблица, где уместно
  • FAQ 5-7 пар; ответы короткие и фактурные
  • Schema BlogPosting + FAQPage; даты datePublished / dateModified актуальны
  • Внутренние ссылки 2-3: главная блога, релевантные landing
  • Внешние ссылки на первоисточники (Вордстат, официальные гайды Google и Яндекс)
  • Нет выдуманной статистики и запрещённых штампов из редакционного контракта
  • Читабельность: прогоните текст вслух - где спотыкаетесь, сократите
  • llms.txt и robots.txt: AI-краулеры не закрыты случайно
  • Обложка 16:9 с крючком; inline - alt по сцене
  • CTA не больше трёх упоминаний офера на статью
  • Финальный island test: вырежьте один H2 - смысл сохраняется?

Делайте: технический QA после редактуры - linter HTML, проверка ссылок. Не делайте: публиковать без сверки FAQ и schema.

Частые вопросы

Сколько символов должно быть в SEO-статье?

Универсальной нормы нет - объём зависит от сложности темы и конкурентов в выдаче. Ориентир для how-to longread: 8 500-9 500 знаков, если SERP требует глубины. Сверьте ТОП-5: если конкуренты дают чек-листы, короткая заметка на 1 500 знаков не закроет запрос.

Что такое GEO в SEO?

GEO (Generative Engine Optimization) дополняет SEO: цель - цитирование в AI-ответах (Яндекс Нейро, Google AI Overviews). База та же - индексируемый, структурированный people-first контент. GEO без индексации и нормальной структуры не работает.

Нужно ли переспамить ключевые слова в 2026 году?

Нет. Поисковики оценивают смысл и полезность; переспам вреден. Используйте primary query в заголовках и lead, secondary и тематические слова - естественно в подзаголовках и абзацах.

Чем Title отличается от H1?

Title - для сниппета в выдаче (около 60-65 знаков, ключ и триггер). H1 - заголовок на странице. Не дублируйте дословно: разные роли, один интент.

Какие schema нужны для SEO-статьи блога?

Минимум BlogPosting (или Article) и FAQPage, если есть блок вопросов. JSON-LD в отдельном файле; текст FAQ должен совпадать с видимым HTML.

Нужен ли llms.txt блогу?

Опциональный сигнал для AI-краулеров; полезен рядом с sitemap, но Google Search не использует llms.txt для ранжирования. Не заменяет robots.txt и нормальную индексацию.

Как проверить статью перед публикацией?

Пройдите чеклист из 15 пунктов: семантика, мета, структура H2, FAQ, schema, ссылки, читабельность, island test по блокам. После - linter HTML, проверка ссылок, slop и каннибализация ключей.
