Текст набирают под ключи, а потом удивляются: в выдаче есть, но никто не дочитывает. SEO-статья в 2026 году - это страница, которая закрывает запрос человека и разбита на блоки, понятные нейропоиску. Ниже один workflow: от проверки SERP до FAQ, JSON-LD и финального чеклиста. После прочтения вы соберете семантику в Вордстате, построите outline longread и опубликуете seo текст для блога без переспама и воды.

TL;DR / Быстрый инсайт: Порядок работы: спрос и задача страницы, затем текст для человека, потом SEO-доработка. Семантику группируют в 3-5 кластеров под H2; после каждого H2 - сразу ответ. GEO дополняет SEO: цель - цитирование в AI-ответах при индексируемом контенте. Минимум техники: Title около 65 знаков, FAQ 5-7 пар, BlogPosting + FAQPage в JSON-LD, llms.txt и island test каждого блока.

SEO-статья отвечает на запрос и читается как нормальный текст. GEO - оптимизация под генеративный поиск (Нейро, AI Overviews). AEO - прямой ответ в первых абзацах. Эта страница - эталон формата: режим B, атомарные H2, один FAQ. Универсального объема нет - ориентир для how-to: 8 500-9 500 знаков по полноте ответа, не по мифической норме.

1. Проверьте интент и SERP перед написанием

Первый шаг - понять, что ждет человек от страницы. Вбейте primary query в поиск, откройте топ-5 результатов и зафиксируйте тип материалов: гайд, чеклист, сравнение или обзор. Запишите обязательные подтемы, которые повторяются у конкурентов. SEO-статья 2026 закрывает интент целиком: если в топе только чеклисты, короткая заметка не выиграет.

Критерий SEO GEO
Цель Клик из выдачи и удержание на странице Цитирование в AI-ответах (Нейро, AI Overviews)
Формат ответа Сниппет Title + Description Короткий фрагмент из H2 или FAQ
Структура H1-H3, списки, внутренние ссылки Атомарные чанки, тезис в первом абзаце секции
Техника Мета, alt, Вордстат, перелинковка Schema JSON-LD, llms.txt, FAQ в HTML

Делайте: составьте таблицу "что есть у конкурента - что сделаете вы". Не делайте: копировать структуру longread один в один без своего угла.

2. Соберите семантику в Вордстате и сгруппируйте кластеры

Семантику собирают в Яндекс Вордстат и Яндекс Вебмастер: primary query, 15-25 LSI-фраз, похожие запросы. Фразы группируют в 3-5 смысловых кластеров - каждый станет будущим H2.

  1. Шаг 1: Зафиксируйте primary query. Для этой темы: "как писать seo статьи". Он идет в H1, lead, Title и 1-2 H2.
  2. Шаг 2: Добавьте secondary. "seo текст для блога" и "geo оптимизация статьи" - в подзаголовки и абзацы естественно.
  3. Шаг 3: Соберите LSI. структура seo статьи, title description h1, faq schema, семантическое ядро - по одному вхождению на блок, без переспама.
  4. Шаг 4: Разложите по кластерам. Например: интент, структура, мета, FAQ/schema, GEO, чеклист.
  5. Шаг 5: Проверьте SERP еще раз. Если в топе только короткие заметки, а ваш how-to требует глубины - объем растет по фактам, не по ключам.

Делайте: пишите заголовки H2 как ответ на реальный вопрос, а не ради ключа. Не делайте: схему "10 000 знаков + 15 ключей" - нормальный порядок: спрос, текст для человека, SEO-доработка.

3. Соберите каркас longread с answer-first блоками

H1 - один на страницу (в теме WordPress). В body - только H2 и H3. После каждого H2 - сразу содержательный ответ в первом абзаце. Главный ключ - в H1, lead, 1-2 H2, Title и Description; LSI - по тексту без искусственных повторов. Lead на 350-500 знаков: боль, суть ответа, результат для читателя - без пустых вводных абзацев.

Схема workflow:
Запрос и интент → семантика (Вордстат) → outline H2/H3 → lead 350-500 знаков → черновик → мета → FAQ → schema JSON-LD → GEO-чанки → чеклист перед публикацией

Title и Description влияют на сниппет и кликабельность. Title - ориентир около 65 знаков, с ключом и триггером (чеклист, гайд). H1 не дублируйте дословно: Title - обещание в выдаче, H1 - заголовок на странице. Абзацы - 3-5 строк по рекомендации Яндекс Директ; списки для перечислений. Поисковики оценивают смысл, не плотность ключей.

Делайте: island test - вырежьте один H2, смысл блока должен сохраниться. Не делайте: длинные "кирпичи" без списков и таблиц там, где нужно сравнение.

4. Напишите черновик для человека, затем доработайте SEO

Черновик - для читателя. ИИ только как черновик с ручной правкой: факты, тон и структура остаются на вас. Страница закрывает задачу пользователя, а не "набор ключей". Если читатель уходит обратно в поиск - сигнал слабого ответа. Нейросети вырезают фрагменты: определения, цифры, сравнения, шаги. Q&A без содержания не помогает.

Делайте: в каждой секции рекомендация "делать / не делать". Не делайте: выдуманные "+140% трафика" без источника.

5. Настройте Title, Description и внутренние ссылки

Description - 100-180 знаков с обещанием. Alt описывает картинку, не ключ. Внутренние ссылки 2-3: главная блога, смежный материал geo оптимизация сайта. Google рекомендует JSON-LD; важнее полнота полей schema, чем их количество. Разметку не дублируйте видимым JSON в body.

Делайте: проверяйте ссылки. Не делайте: больше трех упоминаний одного офера.

6. Добавьте FAQ и schema BlogPosting + FAQPage

FAQ в HTML - готовые чанки для AI и расширенных сниппетов. Вопросы из реальных запросов: объем, GEO, schema, переспам. Базовый набор schema: BlogPosting + FAQPage в JSON-LD; текст FAQ и разметки совпадает. "FAQ + Schema = нейроответ" без полезного текста и доступа краулеров - миф.

Делайте: 5-7 пар по теме. Не делайте: FAQ в schema без HTML на странице.

7. Упакуйте материал под GEO: llms.txt и атомарные чанки

GEO дополняет SEO: цитирование в AI-ответах при индексируемом контенте. llms.txt - подсказка краулерам, не замена sitemap. Проверьте robots.txt: AI-боты не закрыты. Модульные блоки с определениями, цифрами и шагами цитируются чаще - по данным исследований GEO measurement (arxiv 2026).

Делайте: обновляйте dateModified. Не делайте: текст "для робота" без читабельности.

8. Пройдите чеклист перед публикацией

Финальный проход - printable logic. Сохраните список в Notion или таблице и отмечайте пункты по каждой новой статье.

  • Primary query закрыт в lead и H2; secondary вписаны без переспама
  • Title около 65 знаков, отличается от H1; Description с обещанием и ключом
  • Один H1 на странице (в теме WP), в body только H2/H3
  • Каждый H2: тезис в первом предложении, блок понятен без контекста
  • Абзацы 3-5 строк; списки и таблица, где уместно
  • FAQ 5-7 пар; ответы короткие и фактурные
  • Schema BlogPosting + FAQPage; даты datePublished / dateModified актуальны
  • Внутренние ссылки 2-3; внешние - на первоисточники (Вордстат, официальные гайды)
  • Нет выдуманной статистики; llms.txt и robots.txt в порядке
  • Island test и CTA не больше трех упоминаний офера

Делайте: перелинковку со второй статьи. Не делайте: публикацию без QA (linter, ссылки, slop).

Частые вопросы

Сколько символов должно быть в SEO-статье?

Универсальной нормы нет - объем зависит от сложности темы и конкурентов в выдаче. Ориентир для how-to longread: 8 500-9 500 знаков, если SERP требует глубины. Сократите, если добавляете абзацы без новых фактов.

Что такое GEO в SEO?

GEO дополняет SEO: цель - цитирование в AI-ответах (Яндекс Нейро, Google AI Overviews) при индексируемом структурированном контенте. GEO без базового SEO не работает - сначала индексация и полезный текст, потом упаковка под нейропоиск.

Нужно ли переспамить ключевые слова в 2026 году?

Нет. Поисковики оценивают смысл и полезность; переспам вреден. Используйте primary query в заголовках и lead, secondary и LSI - естественно в подзаголовках и абзацах.

Чем Title отличается от H1?

Title - для сниппета в выдаче (около 65 знаков, ключ и триггер). H1 - заголовок на странице. Не дублируйте дословно: разные роли, один интент.

Какие schema нужны для SEO-статьи блога?

Минимум BlogPosting (или Article) и FAQPage, если есть блок вопросов. JSON-LD в отдельном файле или meta; текст FAQ должен совпадать с видимым HTML.

Что такое llms.txt и нужен ли он блогу?

llms.txt - файл-подсказка для AI-краулеров; дополнение к sitemap, не замена индексации. Для блога с нейропоиском - разумный шаг после накопления нескольких материалов.

Как проверить статью перед публикацией?

Пройдите чеклист из раздела выше: семантика, мета, структура H2, FAQ, schema, ссылки, читабельность, island test. Затем технический QA: linter HTML, проверка ссылок, slop и каннибализация ключей.
