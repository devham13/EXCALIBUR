SEO (Search Engine Optimization) - настройка страницы под обычный поиск: чтобы человек нашёл материал и кликнул в сниппет. Мы в редакции Maya AI собираем seo текст для блога по одному контракту: интент, структура, инфостиль, техника. Поисковики оценивают смысл и полезность, а не плотность ключей - переспам в 2026 году вреден. Если читатель возвращается в поиск после вашей страницы, это сигнал низкого качества.

Соберите SEO и GEO в одном workflow

Классическое SEO отвечает на вопрос: найдёт ли человек страницу и кликнет ли в Title с Description. GEO дополняет SEO: цель - цитирование в генеративных ответах, когда пользователь спрашивает нейросеть, а не вводит запрос в строку. GEO не заменяет SEO: без индексации AI просто не увидит ваш текст.

Нейросети извлекают короткие фрагменты (passages), а не страницу целиком. Каждый H2-блок должен быть понятен без соседних абзацев. Первые 40-70 слов страницы - ключевая зона для извлечения ответа AI. Делайте: пишите answer-first после каждого подзаголовка. Не делайте: прятайте суть за вводными "в этой части мы рассмотрим".

Критерий SEO GEO
Цель Клик из выдачи и удержание на странице Цитирование в AI-ответах (Нейро, AI Overviews)
Формат ответа Сниппет Title + Description Короткий фрагмент из H2 или FAQ
Структура H1-H3, списки, внутренние ссылки Атомарные чанки, тезис в первом предложении секции
Техника Мета, alt, Wordstat, перелинковка Schema JSON-LD, FAQ в HTML, доступ AI-краулеров
Схема единого workflow:
Запрос и интент → семантика (Wordstat / Вебмастер) → outline H2-H3 → lead-абзац → текст с чанками → мета → FAQ → schema JSON-LD → чеклист перед публикацией

Что такое GEO в SEO простыми словами

GEO (Generative Engine Optimization) - оптимизация под ChatGPT, Perplexity, Яндекс с Алисой. Цель - попасть в текст ответа как источник, а не только получить клик. Вы упаковываете полезный текст так, чтобы AI мог вырезать определение или шаг. JSON-LD - формат разметки в коде страницы; проверяйте в Google Rich Results Test.

Постройте структуру longread: от семантики до читабельности

Универсального объёма SEO-статьи не существует - он зависит от сложности темы и конкуренции в выдаче. Для how-to longread ориентир 8 500-9 500 знаков: достаточно глубины без воды. Семантику собирают в Яндекс Вордстат и Яндекс Вебмастер: primary query, вторичные запросы, LSI-слова по теме.

Title и Description влияют на сниппет и кликабельность. Title - ориентир 60-65 знаков, с ключом и триггером (чек-лист, гайд). H1 должен отличаться от Title: H1 - заголовок на странице, Title - обещание в выдаче. H1 - один на страницу; H2-H3 для смысловых блоков. Абзацы SEO-текста - ориентир 3-5 строк; списки для перечислений.

  1. Шаг 1: Проверьте спрос и интент. Откройте Wordstat по "как писать seo статьи", зафиксируйте primary и 5-10 LSI; определите тип intent (how-to).
  2. Шаг 2: Разберите SERP. Выпишите 3-5 конкурентов: структура H2, форматы (таблица, FAQ); отметьте пробелы в читабельности.
  3. Шаг 3: Соберите outline. H1 с primary; 4-6 H2 по логике пользователя; блок FAQ 5-7; место под таблицу "ошибка → что делать".
  4. Шаг 4: Напишите lead и черновик. Первые 40-70 слов - прямой ответ; абзацы 3-5 строк; после каждого H2 - суть сразу.
  5. Шаг 5: Встройте семантику. Ключ в H1, lead, 1-2 H2, Title, Description; LSI по тексту без переспама.
  6. Шаг 6: Добавьте GEO-слой. Определение GEO в 40-60 слов; conversational подзаголовки; FAQ с короткими ответами для извлечения AI.
  7. Шаг 7: Оформите мета и медиа. Title 60-65 знаков, Description, alt у изображений; перелинковка; даты и автор.
  8. Шаг 8: Schema и финальный чеклист. BlogPosting + FAQPage; PageSpeed для Core Web Vitals (LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 по web.dev).

Типичная ошибка: писать seo текст для блога как поток ключей. Делайте: один чёткий подзаголовок и короткий абзац. Не делайте: три абзаца без структуры и рекомендации.

Ошибка Как проверить Что делать
Переспам ключей Читаете вслух - текст "ломается" Оставьте primary в H1 и lead, LSI - по смыслу
Title = H1 Сравните два поля Title для сниппета, H1 для страницы - разные формулировки
H2 без ответа Island test: вырежьте блок Первое предложение секции = готовый тезис

Добавьте schema и блок вопросов для выдачи и AI

Блок "Частые вопросы" в HTML - не декор. Вопросы совпадают с реальными запросами: сколько символов, что такое geo, нужна ли schema. Ответы 2-4 предложения - готовые чанки для AI и расширенных сниппетов. Для блога базовый набор - BlogPosting (или Article) плюс FAQPage в JSON-LD; разметка живёт в отдельном файле schema, не дублируется видимым JSON в body.

Schema.org помогает поисковику и нейропоиску сопоставить вопрос и ответ. Текст в FAQ и JSON-LD должен совпадать - расхождение ломает доверие к разметке. Alt описывает содержание картинки, не ключ. Про AI-краулеров и robots.txt - в GEO-оптимизация сайта. Заведите шаблон article.html + article.meta.json + schema.jsonld - один пайплайн на тему, без ручного хаоса перед каждой публикацией.

Пройдите чеклист перед публикацией

Перед выкладкой пройдите список - можно сохранить как шаблон в таблице или Notion.

  • Primary query закрыт в lead и H2; secondary без переспама
  • Title 60-65 знаков, ≠ H1; Description с ключом
  • Один H1 (в теме WP); в body только H2-H3
  • Каждый H2: тезис в первом предложении (island test)
  • Абзацы 3-5 строк; FAQ 5-7 пар
  • Schema BlogPosting + FAQPage; даты актуальны
  • Внутренние ссылки 2-3: главная блога
  • Внешние ссылки на первоисточники (Яндекс Direct, web.dev)
  • Нет выдуманной статистики; E-E-A-T: автор, дата
  • GEO: answer-first; robots не блокирует AI-ботов
  • Core Web Vitals: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1
  • CTA ≤ 3; орфография; Rich Results Test без ошибок
  • Обложка 16:9 с alt по содержанию сцены
  • Island test: вырежьте H2 - смысл сохраняется
  • Нет штампов из slop-blocklist и выдуманной статистики

Нужен системный контент-пайплайн, а не разовый гайд - посмотрите курс Make.com и вайбкодинг: автоматизация research, writer и publish снижает ручную рутину.

Частые вопросы

Сколько символов должно быть в SEO-статье?

Универсальной нормы нет - объём зависит от сложности темы и конкурентов в выдаче. Ориентир для how-to longread: 8 500-9 500 знаков, если SERP требует глубины. Сравните полноту ответа с топ-5 конкурентами, а не считайте знаки ради KPI.

Что такое GEO в SEO?

GEO дополняет SEO: цель - цитирование в AI-ответах (Яндекс Нейро, Google AI Overviews). База та же - индексируемый контент. Начните с answer-first lead и FAQ 5-7 пар, затем добавьте FAQPage в JSON-LD.

Нужно ли переспамить ключевые слова в 2026 году?

Нет. Primary - в H1 и lead, LSI - по смыслу. Прогоните текст вслух: если "скрипит" - уберите лишние вхождения.

Чем Title отличается от H1?

Title - для сниппета (60-65 знаков). H1 - на странице. Не дублируйте дословно.

Какие schema нужны для SEO-статьи блога?

Минимум BlogPosting и FAQPage. JSON-LD отдельно; текст FAQ = видимый HTML.

Как проверить статью перед публикацией?

Пройдите чеклист: семантика, мета, структура H2, FAQ, schema, ссылки, Core Web Vitals, island test. Затем linter HTML, проверка ссылок, slop и каннибализация ключей.

Как писать, чтобы статью цитировали нейросети?

Answer-first в lead и под каждым H2; FAQ с ответами до 80 слов; таблицы и списки; E-E-A-T (автор, дата); не блокируйте AI-краулеров в robots.txt. Обновляйте dateModified при правках.
