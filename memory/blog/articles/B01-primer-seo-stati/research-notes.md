## 4. Угол статьи (utility-only, режим B)

**Главный угол:** SEO-статья 2026 = **читаемый longread**, который закрывает запрос человека **и** упакован для нейропоиска. Не «ещё один список ключей», а **единый workflow**: интент → семантика → структура → черновик → мета/schema → GEO-чанки → **чек-лист 15–20 пунктов**.

**Почему отличается от конкурентов:**

- Яндекс Direct — канон SEO без GEO-слоя и без «читабельность как KPI».
- Агентские гайды — перегруз E-E-A-T-кейсами и CTA.
- GEO-лонгриды не учат писать текст с нуля.
- H1 «которые читают люди» слабо раскрыт в SERP — наш фокус: **инфostиль + атомарные H2** + техника в одном материале.

**Tone:** практично, по-человечески; без корпоративной воды; каждый H2 = подзадача + **рекомендация** (делать / не делать).

**H2-каркас (из карточки + research):**

1. Зачем SEO и GEO в одной статье (не два проекта)  
2. Структура longread: H1–H3, lead, списки, таблицы  
3. FAQ и schema — зачем и как (JSON-LD, не в body)  
4. Чеклист перед публикацией (15–20 пунктов)

**Подтемы внутри блоков:** Wordstat/интент, Title/Description, E-E-A-T lite, answer-first для GEO, BlogPosting + FAQPage.

## 6. FAQ-кандидаты (5–7)

1. **Сколько символов должно быть в SEO-статье?** — универсальной нормы нет; ориентир — полнота ответа и глубина топ-SERP; для how-to longread Excalibur — **8 500–9 500** знаков текста.  
2. **Что такое GEO в SEO?** — GEO дополняет SEO: цель — цитирование в AI-ответах при базе из индексируемого структурированного контента.  
3. **Нужен ли переспам ключей в 2026?** — нет; естественные вхождения + LSI.  
4. **Чем Title отличается от H1?** — Title для сниппета (~60–70 символов), H1 — на странице.  
5. **Какие schema нужны для SEO-статьи блога?** — BlogPosting (или Article) + FAQPage.  
6. **Как проверить статью перед публикацией?** — чек-лист: семантика, мета, структура, FAQ, schema, ссылки, читабельность.  
7. **Как писать seo текст для блога, а не для лендинга?** — глубже раскрыть подтемы, FAQ, перелинковка hub→spoke, меньше коммерческих CTA.

## 7. Черновик чек-листа (15–20 пунктов для writer)

1. Проверен интент запроса (информационный / практический / коммерческий).  
2. Собран кластер ключей (Wordstat или ручной список 15–25 фраз).  
3. H1 один, с главным ключом и явной пользой.  
4. Lead-абзац отвечает на запрос в первых 2–3 предложениях.  
5. H2 закрывают подтемы кластера; после каждого H2 — прямой ответ.  
6. Абзацы 3–5 строк; есть списки/таблица где уместно.  
7. Ключи вписаны естественно (H1, первый абзац, 1–2 H2, title, description).  
8. Title ~60–70 символов; Description ~150–160; H1 ≠ Title дословно.  
9. URL короткий, латиница, без параметров.  
10. Alt у изображений описывает смысл, не «seo картинка».  
11. 3–5 внутренних ссылок на релевантные материалы.  
12. Блок FAQ 5–7 вопросов с короткими ответами-действиями.  
13. JSON-LD BlogPosting + FAQPage (schema-агент).  
14. Answer-first блоки для GEO (определения, нумерованные шаги).  
15. Убрана «вода» и шаблоны («в современном мире», «важно отметить»).  
16. Есть маркеры экспертности: автор, пример, кейс или конкретный инструмент.  
17. Факты только из research / fact-bank — без выдуманных %.  
18. Прочитано вслух / island test: каждый H2 понятен отдельно.  
19. CTA ≤ 3, не подменяют пользу.  
20. Даты datePublished / dateModified актуальны на 2026-08-09.

## 9. Utility gate (research)

**utility_verdict:** PASS

**reader_outcome:** Читатель за один цикл (от брифа до публикации) напишет SEO-статью для блога: определит интент, соберёт семантику, соберёт структуру H1–H3, напишет читаемый longread с FAQ и schema, добавит GEO-чанки (answer-first) и пройдёт чек-лист из 15–20 пунктов перед публикацией.

**action_outline:**

1. **Проверить спрос и интент:** открыть топ-10 по «как писать seo статьи», зафиксировать формат (гайд/чек-лист), тип интента, пробелы конкурентов.  
2. **Собрать семантический кластер:** Wordstat/Вебмастер — 15–25 фраз; сгруппировать по подтемам; один кластер = одна статья.  
3. **Собрать структуру:** H1 + 4–6 H2 из карточки и кластера; под каждым H2 — тезис первого предложения и список фактов/примеров.  
4. **Написать черновик «сначала смысл»:** lead с прямым ответом; абзацы 3–5 строк; таблица или список в каждом крупном блоке.  
5. **Встроить ключи и LSI естественно:** главный ключ в H1, lead, 1–2 H2; без переспама.  
6. **Усилить E-E-A-T lite:** автор, один конкретный пример/инструмент, исходящая ссылка на авторитет (Яндекс Direct / первичник).  
7. **Оформить технику:** Title, Description, URL, alt; 3–5 внутренних ссылок.  
8. **Добавить FAQ + GEO-слой:** 5–7 Q&A; answer-first определения; handoff schema BlogPosting + FAQPage.  
9. **Финальный чек-лист:** пройти 20 пунктов раздела 7; исправить «воду» и блоки без рекомендации «что делать».
