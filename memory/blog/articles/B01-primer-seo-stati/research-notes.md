**Паттерн SERP (август 2026):** доминируют «полный гайд 2026» с чек-листом, E-E-A-T и блоком про нейровыдачу. Прямого совпадения с H1 «которые **читают люди**» мало — конкуренты говорят про «топ» и «роботов», но слабо связывают **читабельность** (инфостиль, сканирование, поведенческие сигналы) с **GEO-упаковкой** в одном workflow.

**Intent:** `how_to` — пользователь хочет пошаговую систему от семантики до публикации. Вторичный: понять связку SEO + GEO в одном материале, не в двух разрозненных гайдах.

**Пробел для Excalibur:** meta-статья режима B — **сама демонстрирует формат**, который учит: longread для людей + answer-first для AI + чеклист 15–20 пунктов + FAQ/schema handoff. Угол **автоматизатора контента**, не «копирайтинг ради ключей».

## 4. Угол статьи (utility-only, режим B)

**Главный угол:** SEO-статья 2026 = **читаемый longread**, который закрывает запрос человека **и** упакован для нейропоиска. Единый workflow: интент → семантика → структура → черновик для людей → GEO-слой (answer-first, FAQ) → техника (Title/Description/schema) → **чеклист перед публикацией**.

**Почему отличается от конкурентов:**
- Яндекс Direct — канон SEO без GEO и без «читабельности как фактора».
- Агентские гайды — перегружены кейсами и CTA; мало meta-демонстрации формата.
- GEO-гайды не учат писать текст с нуля.
- H1 «которые читают люди» — слабо раскрыт в SERP; наш фокус: **инфостиль + сканирование + острова смысла** в одном материале с B04.

**Режим B:** сама статья B01 — **эталон**: 8 500–9 500 знаков, 5–7 FAQ, BlogPosting + FAQPage (schema — отдельная роль), атомарные H2, lead с определением.

**H2-каркас (из карточки + research):**
1. Зачем SEO и GEO в одной статье
2. Структура longread: H1–H3, lead, списки, таблицы
3. FAQ и schema — зачем и как (JSON-LD handoff, не в body)
4. Чеклист перед публикацией (15–20 пунктов)

## 6. FAQ-кандидаты (5–7)

1. **Сколько символов должно быть в SEO-статье?** — универсальной нормы нет; ориентир — полнота ответа и топ SERP; для how-to longread Excalibur — 8 500–9 500 знаков.
2. **Что такое GEO в SEO?** — GEO дополняет SEO: цель — цитирование в AI-ответах при базе индексируемого структурированного контента.
3. **Нужно ли переспамить ключевые слова в 2026 году?** — нет; естественные вхождения + LSI/синонимы.
4. **Чем Title отличается от H1?** — Title для сниппета (~50–65 знаков), H1 — заголовок на странице; не дублировать дословно.
5. **Какие schema нужны для SEO-статьи блога?** — BlogPosting (или Article) + FAQPage для блока вопросов.
6. **Как проверить статью перед публикацией?** — чеклист: семантика, мета, структура, FAQ в HTML, schema, ссылки, читабельность.
7. **Можно ли публиковать текст только от нейросети?** — можно, если есть уникальная ценность и редактура; массовая генерация без экспертизы — риск спама.

## 7. Черновик чек-листа (15–20 пунктов для writer)

1. Primary query и 10–15 LSI собраны (Wordstat / Вебмастер).
2. Интент определён по топ-5 SERP (how-to, не «что такое» без шагов).
3. H1 один; Title 50–65 знаков, не копирует H1.
4. Description 140–180 знаков — ответ + польза.
5. Lead: прямой ответ в первых 40–60 словах.
6. H2 закрывают кластер; после каждого H2 — тезис в первом абзаце.
7. Абзацы 3–5 строк; списки и таблицы там, где сравнение/шаги.
8. Ключ в H1, lead, 1–2 H2; LSI распределены естественно.
9. Нет воды и штампов («в современном мире», «стоит отметить»).
10. Есть маркер экспертности: пример, цифра с URL или кейс.
11. FAQ 5–7 вопросов в **видимом HTML** (не только в schema).
12. 2–3 внутренние ссылки на hub/смежные гайды.
13. Alt у изображений описывает содержание, не ключи.
14. JSON-LD BlogPosting + FAQPage готовы к handoff schema-роли.
15. Island test: каждый H2 actionable без контекста соседей.
16. Объём longread 8 500–9 500 знаков (или обоснованно больше по SERP).
17. Прочитан вслух / «тест клиента»: захотите ли поделиться?
18. Дата публикации/обновления указана (видимо + в meta).

## 9. Utility gate (research)

**utility_verdict:** PASS

**reader_outcome:** Читатель соберёт семантику по запросу, построит структуру longread с answer-first блоками и FAQ, оптимизирует Title/Description/H1, подготовит handoff для BlogPosting + FAQPage и пройдёт чеклист из 15–20 пунктов перед публикацией SEO-статьи, которую дочитают люди и смогут процитировать нейросети.

**action_outline:**

1. **Определить интент:** открыть топ-5 SERP по primary query; зафиксировать формат (гайд/чек-лист) и список подтем конкурентов.
2. **Собрать семантику:** primary + 10–15 LSI в Wordstat/Вебмастер; отсечь нерелевантные «хвосты».
3. **Составить скелет до текста:** H1, 4–6 H2 из карточки + кластера; часть H2 — вопросы из faq_hints.
4. **Написать черновик для человека:** lead с ответом; короткие абзацы; списки/таблицы; без переспама ключей.
5. **Добавить GEO-слой:** после каждого H2 — атомарный ответ; FAQ 5–7 в видимом HTML; не прятать ответы только в аккордеон.
