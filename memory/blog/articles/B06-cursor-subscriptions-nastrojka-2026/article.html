1. Сравните Subscriptions и Automations: что выбрать

Automations – постоянные правила в UI на cursor.com/automations: каждый trigger (cron, webhook, новый PR) создаёт новый cloud agent run. Subscription оформляет уже работающий agent: он ждёт события на конкретном PR или в конкретном Slack-треде и продолжает ту же задачу.

Критерий Automations Subscriptions
Где настраивается UI правил на cursor.com/automations В running cloud agent: промпт или /subscribe
Модель работы One-shot: событие → новый run Stateful: agent спит и просыпается на том же PR/thread
Когда брать Cron-digest, triage каждого нового PR "Доведи этот PR до merge", "жди ответ в этом Slack-треде"
Срок жизни Каждый run отдельно До 180 дней или пока agent решит, что wait окончен
Итоговый вердикт: Automations – для массовых триггеров по расписанию. Subscriptions – когда нужен один PR или один тред без ручного babysitting в чате.

Делайте: Automations для ежедневного triage, Subscription для задачи "довести до merge". Не делайте: путать с оплатой Cursor Pro – это разные сущности.

2. Подключите GitHub, Slack и spend limit в Dashboard

Cloud agents доступны на всех paid планах Cursor. Перед первым run Cursor попросит spend limit – лимит расходов на облачные запуски (как prepaid на телефоне: без него agent не стартует).

Workflow настройки:
Проверка плана → dashboard/integrations (GitHub + Slack) → dashboard/spending (лимит) → cloud environment (repo + secrets) → первый agent run
  1. Шаг 1: Откройте Cloud Agents dashboard и убедитесь, что раздел Environments доступен на вашем плане.
  2. Шаг 2: На dashboard/integrations нажмите Connect у GitHub – выберите All repos или Selected repos (только нужные репозитории).
  3. Шаг 3: Connect Slack → установите app → привяжите repo provider → включите usage-based pricing → подтвердите privacy.
  4. Шаг 4: На dashboard/spending включите on-demand и задайте monthly spend limit до первого cloud run.
  5. Шаг 5: Создайте cloud environment: укажите repo, добавьте secrets только через Dashboard (не в промпт), выполните Test run / Build.

Делайте: Selected repos на проде – меньше поверхность атаки. Не делайте: писать API-ключи и пароли в текст промпта – только secrets в Dashboard.

3. Настройте автоподписку на PR: CI и bot-комментарии

Cloud agent, который сам открыл PR, автоматически подписывается на него: чинит CI на GitHub Actions и отвечает на bot-комментарии. Подписку можно задать промптом ("open a PR and keep it green until merge") или skill /subscribe. GitHub events: комментарии и reviews, lifecycle PR, CI на branch.

Auto-fix CI – только GitHub Actions; официально для Teams, иначе "@cursor fix CI" в комментарии. Вкл/выкл: @cursor autofix on/off. Лимит: до 10 autofix follow-ups на PR; не срабатывает после human commit или того же failing check на base.

  1. Шаг 1: Запустите cloud agent через web/agents или @Cursor agent [prompt] в Slack с задачей и merge-критерием.
  2. Шаг 2: Дождитесь, пока agent создаст PR – проверьте auto-subscription в Run History.
  3. Шаг 3: Симулируйте failing check или дождитесь реального CI – agent должен re-wake (bursts coalesce: несколько событий подряд → один wake).
  4. Шаг 4: На тестовом PR проверьте @cursor autofix off, если autofix мешает отладке.
  5. Шаг 5: Убедитесь, что subscription активна не дольше 180 дней – agent отпишется, когда wait завершён.

Делайте: формулируйте DoD в промпте ("green CI until merge"). Не делайте: ждать autofix на GitLab CI – поддерживается только GitHub Actions.

4. Настройте мониторинг Slack-треда: wake-on-reply

Slack integration даёт agent доступ к replies в thread, channel messages и новым public channels. Пример из changelog: @cursor check back in an hour and keep going until that feedback is in – agent подписывается на тред и возвращается по таймеру или при новом reply.

В Slack: @Cursor help и @Cursor agent [prompt]. Routing rules в Dashboard задают repo и environment.

  1. Шаг 1: В треде, где уже работает agent, напишите критерий "done" и интервал check-back.
  2. Шаг 2: Ответьте в треде от имени коллеги – agent должен проснуться и продолжить (steering: follow-up ждёт следующий tool call, не прерывает текущее действие).
  3. Шаг 3: Проверьте Run History на cursor.com/dashboard/cloud-agents – видны wake и re-read source.

Делайте: один тред – одна подписка с ясным критерием завершения. Не делайте: дублировать ту же задачу в Automations – получите параллельные runs вместо одного stateful agent.

5. Закрепите длинные задачи: /goal, /in-cloud и /autopilot

/goal – long-lived objective ("fix flaky tests, CI green"). Subagents через /in-cloud на изолированных VM. PR до merge-ready: /autopilot (alias /babysit) или skill ce-babysit-pr. Таймеры: /loop или cron. Custom Mode: skill через / + Alt+Enter. Связка /goal + subscription снимает ручной re-prompt.

Делайте: /goal для задач с чётким DoD на дни. Не делайте: смешивать /autopilot и отдельную Automation на тот же PR – agent может дублировать работу.

6. Пройдите чек-лист безопасности перед production repo

  • Paid план Cursor и spend limit задан до первого run
  • GitHub: Selected repos, не All, если не нужен полный доступ
  • Slack: usage-based pricing осознанно включён; privacy подтверждена
  • Secrets только в Dashboard environment, не в промпте и не в Git
  • Test run / Build cloud environment пройден до production задачи
  • Run History проверен после первого subscription wake
  • На тестовом PR проверен @cursor autofix off при отладке
  • Linear integration (если используете) – только нужные проекты
  • Routing rules Slack – agent не уходит в чужой repo
  • Team MCP для внешних tools – по инструкции MCP, keys в env
  • Subscription max 180 days – пересмотрите long-running /goal раз в квартал
  • Human-in-the-loop: merge PR подтверждает человек, не agent

Делайте: старт на sandbox-repo, потом перенос workflow. Не делайте: давать agent write-доступ ко всем org repos без review правил.

Частые вопросы

Чем Subscriptions отличается от Automations в Cursor?

Automations – правило в UI на cursor.com/automations: каждый trigger запускает новый cloud agent run. Subscription держит running agent на конкретном PR или Slack-треде до завершения задачи. Для "довести этот PR" берите Subscription; для cron-digest каждого PR – Automations.

Как попросить Cursor следить за pull request?

Запустите cloud agent с промптом вроде "implement X, open PR, keep it green until merge" или добавьте skill /subscribe с вашей целью. Agent автоматически подписывается на PR, которые сам создал. Проверьте wake в Run History на dashboard/cloud-agents.

Может ли Cursor мониторить Slack-тред?

Да, при подключённой Slack integration и running cloud agent. Напишите в треде, например: @cursor check back in an hour and keep going until that feedback is in. Agent проснётся по таймеру или при новом reply в thread.

Нужен ли Teams для auto-fix CI?

По документации Cursor auto-fix CI failures официально для Teams; на других paid планах явно попросите agent починить CI в комментарии к PR или промпте. Autofix работает только с GitHub Actions, не с другими CI.

Работают ли Subscriptions в локальном Agent?

Нет. Subscriptions доступны только для cloud agents в облаке Cursor. Локальный Agent в IDE не держит subscription на PR или Slack – нужен cloud run через Dashboard или @Cursor в Slack.

Сколько живёт subscription?

Максимум 180 дней. Agent отписывается раньше, когда решает, что wait завершён (критерий done из вашего промпта). Для задач длиннее периодически пересматривайте /goal и Run History.

/babysit или /autopilot для PR?

На desktop используйте /autopilot; /babysit – search alias после переименования. Альтернатива – skill ce-babysit-pr из Marketplace: watch PR until merge-ready (review, CI, движение base branch).
