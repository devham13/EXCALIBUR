Заявки приходят в Telegram и с сайта, а менеджеры узнают о сделке с опозданием или вручную переносят лиды в amoCRM. Связка amoCRM и n8n закрывает разрыв без программиста: OAuth, webhook и уведомления в мессенджер собираются в визуальном редакторе. Ниже два рабочих контура - входящая заявка в воронку и исходящее "статус изменился" в Telegram - плюс защита от дублей и чеклист перед включением workflow в production.

TL;DR / Быстрый инсайт: Официального узла amoCRM в n8n нет - используйте community-пакет n8n-nodes-amocrm на self-host или HTTP Request с OAuth2. Вход: Webhook или Telegram Trigger → нормализация телефона и UTM → POST /api/v4/leads/complex. Выход: webhook из amoМаркет на Production URL n8n (workflow должен быть Active). Лимит amoCRM: до 7 запросов в секунду на интеграцию; при 429 - пауза и retry. Не регистрируйте в CRM Test URL webhook - amoCRM шлет только на production.

Интеграция amoCRM и n8n - no-code мост между CRM, сайтом и Telegram. API - "розетка" для обмена данными; webhook - когда CRM сама шлет POST на URL n8n при смене сделки. Self-host требует HTTPS и WEBHOOK_URL для Telegram. Community-узлы на n8n Cloud не ставятся без verified статуса - тогда HTTP Request.

1. Сравните, когда amoCRM + n8n выгоднее Make и Zapier в 2026

Для РФ-бизнеса amoCRM - база воронки. n8n выигрывает при self-host, сложных webhook и контроле RPS API. Make быстрее стартует из браузера. Zapier на объеме часто дороже.

2. Настройте OAuth и credentials amoCRM в n8n

Официального amoCRM-узла в n8n нет. Пакет n8n-nodes-amocrm (0.0.17 на npm) ставится на self-host через Community Nodes. Альтернатива - long-lived token private integration.

  1. Создайте внешнюю интеграцию в amoCRM → amoМаркет: scopes на leads и contacts, скопируйте Integration ID, Secret и subdomain аккаунта.
  2. Добавьте credential в n8n для community-узла или OAuth2 для HTTP Request: вставьте ID и Secret.
  3. Скопируйте Redirect URL из n8n и вставьте в поле Redirect Link интеграции amoCRM посимвольно (https, слэш в конце - как в n8n).
  4. Нажмите Connect my account в n8n до зеленого статуса или сохраните long-lived token для HTTP-варианта.
  5. Проверьте тестовый GET к /api/v4/account в HTTP Request - код 200, не 401.

401 - неверный token или просрочен OAuth. 403 на все API - аккаунт мог заблокировать за превышение лимита запросов. Делайте: один credential на все workflow amoCRM. Не делайте: править Redirect URL "на глаз" - типичная причина бесконечного OAuth.

3. Соберите входящую заявку: Webhook или Telegram → lead в amoCRM

Схема inbound:
Источник (Webhook POST / Telegram Trigger) → Set или Code: имя, phone E.164, UTM, source → опционально GET /api/v4/contacts?query=phone → If дубль → amoCRM Create Complex или HTTP POST /leads/complex → Respond to Webhook 200

Production URL webhook n8n работает только при Active workflow; лимит payload - 16 MB. Telegram на self-host без HTTPS и WEBHOOK_URL не заведется.

  1. Выберите триггер: Webhook (форма сайта) или Telegram Trigger (сообщение боту).
  2. Нормализуйте поля: телефон в E.164, email, utm_source, utm_campaign, метка источника.
  3. Укажите pipeline_id и status_id тестовой воронки amoCRM - не прод, пока не проверите поля.
  4. Отправьте POST /api/v4/leads/complex - сделка, контакт и опционально компания за один запрос (до 50 сделок за запрос; на одну сделку не более 1 контакта и 1 компании).
  5. Ответьте источнику 200 через Respond to Webhook, чтобы форма не повторяла отправку.
  6. Откройте Executions и зафиксируйте id сделки, merged-флаг, отсутствие 422.
Блок Задача Быстрая проверка
Inbound webhook Заявка с сайта в CRM Production URL + Active, тело complex с pipeline_id
Telegram Trigger Лид из чата HTTPS, WEBHOOK_URL, bot token от BotFather

Делайте: сначала одну воронку "Тест n8n". Не делайте: писать в прод-воронку до проверки custom fields (лимит до 40 полей на сущность в complex).

4. Настройте исходящий webhook amoCRM → фильтр статуса → Telegram

Исходящие webhook amoCRM - POST x-www-form-urlencoded (entity → action). Настройка в amoМаркет или через POST /api/v4/webhooks; API-webhook - с расширенного тарифа.

  1. Создайте второй workflow с Webhook node, скопируйте Production URL.
  2. В amoМаркет добавьте исходящий webhook на смену статуса сделки (update_lead / status_lead по вашей настройке).
  3. Активируйте workflow - без Active amoCRM бьет в нерабочий или test endpoint.
  4. Добавьте IF: pipeline_id и status_id равны целевым (например "Договор отправлен").
  5. Telegram Send Message: token бота и chat_id менеджера или группы продаж.

Делайте: короткий текст уведомления: id сделки, имя, новый статус, ссылка на карточку в amoCRM. Не делайте: в этом же workflow без guard снова обновлять ту же сделку - получите петлю webhook.

5. Включите защиту от дублей и webhook-петель

Дубли портят отчеты; петля webhook быстро дает 429 (лимит 7 rps на интеграцию) и риск 403 на API.

  • Поиск перед созданием: GET /api/v4/contacts?query=phone или email; при совпадении - только привязка или обновление, не новый complex.
  • Idempotency: храните обработанные entity id + timestamp в static data workflow или во внешней таблице; повторный webhook с тем же id - Stop.
  • Webhook guard: исходящий сценарий не вызывает Update Lead без условия "поле изменилось не этим workflow".
  • Rate limit: node Wait между пачками; batch изменений amoCRM рекомендует не более 50 сущностей, максимум 250 в одном запросе.
  • Error Workflow: при 401/429 отправьте алерт в Telegram и остановите цепочку.

Делайте: включите контроль дублей для интеграции в настройках amoCRM, если доступно для вашего сценария. Не делайте: гонять десятки HTTP-нод подряд без пауз - словите 429.

6. Пройдите чеклист перед продакшеном

  • Workflow inbound и outbound переключены в Active.
  • В amoCRM и формах указан только Production URL webhook n8n.
  • HTTPS на домене n8n; для self-host задан WEBHOOK_URL.
  • На публичном inbound webhook включена Header Auth или другой секрет в URL.
  • Тестовая воронка отработала; prod pipeline_id и status_id перенесены осознанно.
  • OAuth credential общий; срок token проверен.
  • Telegram bot добавлен в нужный chat; chat_id верный.
  • Executions без 401, 422, 429 на типовой заявке.
  • Error Trigger или Error Workflow шлет сообщение дежурному.
  • Нагрузочный тест не превышает 7 rps на интеграцию.
  • Документированы id воронки и ответственный менеджер.
  • Резервная копия JSON workflow экспортирована из n8n.

Self-host поднимается по гайду установка n8n на Docker и VPS. Следующий уровень - связать CRM с AI-агентами: автоматизация n8n с AI Agent.

Частые вопросы

Как подключить amoCRM к n8n без программиста?

Создайте внешнюю интеграцию в amoМаркет, заведите credential в n8n, совместите Redirect URL, нажмите Connect my account. На self-host установите n8n-nodes-amocrm; на n8n Cloud используйте HTTP Request с OAuth2, если пакет не verified.

Нужен ли программист для Telegram и webhook?

Нет для типового сценария: нужен админ amoCRM с правами интеграций и человек, который поднимет n8n с HTTPS для Telegram и внешних webhook.

Почему n8n не создает лид в amoCRM?

Откройте Executions: проверьте OAuth (401), pipeline_id и status_id, тело POST /leads/complex и код 422. Часто ошибка в custom field или неверный subdomain.

Test URL или Production URL для amoCRM?

amoCRM и формы сайта должны слать на Production URL. Test URL работает только пока вы слушаете webhook в редакторе n8n.

Что делать при ошибке 429 от amoCRM?

Добавьте Wait и Retry, снизьте частоту ниже 7 rps на интеграцию, дробите пакеты до 50 сущностей и не запускайте петли webhook.

Как не плодить дубли контактов?

Перед complex ищите контакт по телефону или email; при совпадении обновляйте или привязывайте lead. Включите idempotency по id события webhook.

Работает ли community amoCRM node в n8n Cloud?

Облако n8n ставит только verified community nodes. Если n8n-nodes-amocrm недоступен - соберите сценарий на HTTP Request и OAuth2 credential или перенесите n8n на self-host.
