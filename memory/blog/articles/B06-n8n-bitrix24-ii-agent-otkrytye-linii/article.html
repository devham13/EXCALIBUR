Клиент пишет в Telegram, менеджер отвечает через час, лид теряется, а CRM снова плодит дубли сделок. Встроенный BitrixGPT не ведёт внешний мессенджер сам: для открытых линий нужен чат-бот и связка с n8n. Ниже - пошагово поднимете MVP: Telegram в контакт-центре, webhook на n8n, AI Agent для ответа в том же диалоге, лид без повторов и эскалация человеку с учётом лимита REST 2 запроса в секунду.

TL;DR / Быстрый инсайт: ИИ-агент n8n в открытых линиях - это не CRM-webhook, а зарегистрированный бот v2: событие ONIMBOTV2MESSAGEADD, фильтр entityType=LINES, ответ через imopenlines.bot.session.message.send. Схема: Telegram → открытая линия → HTTPS webhook n8n → AI Agent → REST в Битрикс24 → при квалификации imopenlines.crm.lead.create или crm.item.add с idempotency. Не гоните API быстрее 2 rps на обычных тарифах.

ИИ-агент n8n в открытых линиях - внешний "мозг" поверх Битрикс24: языковая модель отвечает клиенту в чате, а n8n решает, когда создать лид и когда позвать оператора. Webhook - это публичный URL, на который портал "стучится" при новом сообщении; REST API - набор методов для ответа и записи в CRM из n8n.

Типичная ошибка: повесить исходящий webhook только на onCrmLeadAdd и ждать двусторонний чат. Для диалога нужны события бота ONIMBOTV2* и методы imopenlines.*. Шаблон n8n #3094 с RAG полезен позже; для первого вечера хватит одного AI Agent без векторной базы.

Цепочка MVP:
Клиент в Telegram → открытая линия Битрикс24 → ONIMBOTV2MESSAGEADD → Webhook n8n → фильтры → AI Agent → imopenlines.bot.session.message.send → (опционально) imopenlines.crm.lead.create → при риске imopenlines.bot.session.operator

1. Выберите, когда n8n нужен поверх BitrixGPT и CoPilot

CoPilot и BitrixGPT помогают сотруднику внутри портала, но не подменяют зарегистрированного чат-бота в мессенджере. Для Telegram через открытые линии нужен бот с type=openline или bot плюс isSupportOpenline=true, как в официальном tutorial.

Критерий BitrixGPT / CoPilot Внешний агент в n8n
Диалог в Telegram OL Нет автономного канала Да, через бота v2 и webhook
Своя модель и промпт Ограничено экосистемой OpenAI, Anthropic и др.
Human-in-the-loop Оператор вручную Правила в Switch + transfer оператору
Сложность старта Низкая для текста в CRM Бот, scopes, n8n workflow

Делайте: n8n, если нужны свои модели, ветвления и интеграции вне маркетплейса. Не делайте: обещать клиенту "только входящий webhook" без imbot.v2.Bot.register - для OL это тупик.

Self-hosted n8n (свой сервер вместо облака SaaS) снижает накладные на медиа и даёт контроль логов; для MVP подойдёт n8n Cloud с Production URL, если есть HTTPS.

2. Настройте Битрикс24: открытая линия, Telegram и REST-доступ

  1. Проверьте роли. Нужен администратор портала и пользователь, от имени которого зарегистрируете бота (права imbot и imopenlines).
  2. Создайте открытую линию в CRM → Клиенты → Контакт-центр и подключите Telegram. Один канал одного типа - только одна линия: второй Telegram потребует второй линии (справка OL).
  3. Создайте входящий webhook с scopes imbot, imopenlines, crm. Сохраните базовый REST URL в credential n8n; токен не публикуйте в логах и скриншотах.
  4. Зарегистрируйте бота методом imbot.v2.Bot.register: укажите handler URL - Production webhook n8n (POST, HTTPS). Тип openline для чистого OL-сценария.
  5. Привяжите бота к линии в настройках контакт-центра, чтобы сообщения клиента шли на ваш handler.

Делайте: сразу проверьте, что payload содержит data.chat.entityType === LINES. Не делайте: путать входящий REST URL (n8n вызывает API) с адресом handler бота (Битрикс24 шлёт события на n8n).

3. Соберите workflow в n8n: webhook, фильтры и AI Agent

В n8n штатной CRM-ноды для Bitrix24 в core нет: ответы идут через HTTP Request, как в каталоге интеграций n8n.

  1. Добавьте Webhook node (POST), скопируйте Production URL в регистрацию бота.
  2. IF: event = ONIMBOTV2MESSAGEADD и entityType = LINES - иначе игнорируйте шум.
  3. IF: сообщение не от оператора и не эхо бота (фильтр по authorId / system flags - иначе агент ответит на реплику менеджера).
  4. AI Agent node: Chat Model (OpenAI/Anthropic), System Message - тон, запрет выдумывать цены, фразы для эскалации ("человек", "жалоба").
  5. HTTP Request: POST на .../imopenlines.bot.session.message.send.json с CHAT_ID из payload и текстом агента.
  6. Throttle: не более 2 запросов в секунду к одному порталу на тарифах ниже Enterprise (лимиты REST); при QUERY_LIMIT_EXCEEDED - пауза и retry.

Делайте: короткий system prompt на 10-15 строк и одну ветку эскалации. Не делайте: тянуть RAG и Qdrant в первый день - это отдельный проект после стабильного echo-ответа.

Базовый n8n для агентов разобран в гайде автоматизация n8n и AI-агенты; здесь тот же AI Agent, но триггер - не Chat UI, а webhook OL.

4. Настройте CRM: лид из диалога и защита от дублей

Когда агент собрал телефон или email, фиксируйте контакт в CRM один раз на диалог.

  • Быстрый путь OL: imopenlines.crm.lead.create с CHAT_ID из сессии (scope imopenlines). Успех - result: true; ошибки CHAT_TYPE, ACCESS_DENIED, ERROR_USER_NOT_OPERATOR смотрите в документации.
  • Универсальный путь: crm.item.add (entityTypeId 1 для лида) - legacy crm.lead.add помечен устаревшим для новых интеграций.
  • Dedup: перед созданием ищите контакт по телефону; idempotency key = message_id или hash chatId+дата в Static Data n8n или маленькой БД.
  • Повтор webhook: Битрикс24 может прислать событие дважды - без ключа получите вторую сделку на тот же чат.

Делайте: логируйте CRM-ответ в n8n Executions. Не делайте: создавать новую сделку на каждое сообщение клиента.

5. Включите эскалацию оператору (human-in-the-loop)

Сложные неструктурированные диалоги без человека закрываются редко; норма - явная передача оператору при неуверенности модели, негативе или запросе живого менеджера.

  1. Switch после AI Agent: если confidence низкий или ключевые слова - ветка operator.
  2. HTTP Request: imopenlines.bot.session.operator с CHAT_ID (tutorial OL-бота).
  3. Уведомление: опционально Telegram менеджерам через n8n - отдельный бот, не путать с клиентским каналом OL.

Делайте: пропишите в System Message, когда агент обязан молчать и звать человека. Не делайте: бесконечный цикл, где бот спорит с клиентом после transfer.

6. Проверьте прод: лимиты, тесты и мониторинг

Один REST-запрос в облаке может ждать до 60 секунд; при 2 rps теоретический потолок около 172 800 запросов в сутки - для малого бизнеса достаточно, если не слать пачками без пауз.

  • Тест из Telegram как клиент: вопрос → ответ агента в том же чате OL.
  • Тест эскалации: фраза "соедините с оператором" → диалог у менеджера.
  • Тест CRM: один телефон → один лид; повтор того же webhook → без второго лида.
  • Тест фильтра: сообщение оператора не вызывает ответ бота.
  • Мониторинг QUERY_LIMIT_EXCEEDED и HTTP 503 в логах n8n.
  • Batch и задержки между HTTP Request к порталу.
  • Ротация webhook-токена при утечке в лог.
  • Резервная копия workflow JSON в git.
  • Документ scopes и ответственного админа портала.
  • Алерт в Telegram при 5+ ошибках подряд на webhook.
  • Отключение workflow в n8n при обслуживании портала.
  • Проверка SSL на Production URL webhook.

Делайте: приёмку в три прогона (чат, CRM, лимиты). Не делайте: включать прод без фильтра LINES - бот начнёт отвечать не в тех чатах.

Частые вопросы

Как подключить n8n к Битрикс24 через webhook для открытых линий?

Зарегистрируйте бота imbot.v2.Bot.register с handler = Production URL webhook n8n, scopes imbot и imopenlines. В workflow слушайте ONIMBOTV2MESSAGEADD, фильтруйте LINES, отвечайте imopenlines.bot.session.message.send с CHAT_ID из payload.

Чем входящий webhook отличается от исходящего для OL?

Входящий REST URL нужен n8n, чтобы вызывать API Битрикс24. События чата приходят на URL handler бота, а не на CRM event.bind. Исходящий webhook на onCrmLeadAdd не заменит ONIMBOTV2*.

Как ИИ-агент создаёт лид в Битрикс24?

После сбора контакта вызовите imopenlines.crm.lead.create по CHAT_ID или crm.item.add с полями лида. Перед созданием найдите контакт по телефону и проверьте idempotency key, чтобы повтор webhook не создал дубль.

Почему дублируются сделки в открытых линиях?

Чаще всего workflow создаёт CRM-сущность на каждое сообщение или не обрабатывает повтор дelivery webhook. Храните ключ message_id, обновляйте существующий лид вместо слепого add.

Когда передать диалог оператору?

При запросе человека, негативе, юридических темах или низкой уверенности модели. Вызовите imopenlines.bot.session.operator и остановите автоответы агента в этом чате.

Какие scope минимально нужны?

imbot и imopenlines для чата; crm - если пишете лиды из того же webhook-пользователя. Без imopenlines методы сессии OL вернут ACCESS_DENIED.
