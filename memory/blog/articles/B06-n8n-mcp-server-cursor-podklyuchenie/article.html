Cursor видит ваш код, но не видит CRM, почту и сценарии n8n, пока вы не подключите n8n mcp server. Два официальных пути: instance-level MCP (один URL на весь инстанс) и MCP Server Trigger (узкий набор tools из одного workflow). Ниже вы выберете режим под задачу, включите доступ в n8n, пропишете n8n mcp cursor в конфиге и проверите tools в Agent без путаницы test/production URL.

TL;DR / Быстрый инсайт: Instance-level MCP в n8n дает Cursor центральную точку /mcp-server/http: поиск и запуск workflow с пометкой Available in MCP. MCP Server Trigger публикует отдельный production URL с фиксированными tools (например, один tool "создать лид"). В Cursor используйте streamable-http или one-click OAuth из n8n; Bearer-ключ показывают один раз. Не подменяйте community-пакет n8n-mcp встроенным MCP n8n.

MCP (Model Context Protocol) - "розетка" для внешних действий из ИИ-редактора; n8n - ваши сценарии (CRM, почта, webhooks). Базовая настройка MCP в IDE - в гайде по подключению MCP в Cursor; агенты внутри n8n - в материале про автоматизацию n8n. Здесь только связка n8n mcp server и Cursor.

Выберите режим: MCP Server Trigger или instance-level MCP

Делайте: зафиксируйте задачу одним предложением ("запускать любые опубликованные workflow из Cursor" vs "дать Cursor ровно три tools для CRM"). Не делайте: не смешивайте URL Trigger и /mcp-server/http в одной записи mcp.json - это разные серверы.

Критерий Instance-level MCP MCP Server Trigger
Задача в Cursor Искать, запускать, при необходимости собирать workflow в инстансе Вызвать фиксированный набор tools из одного сценария
URL для Cursor https://<домен>/mcp-server/http Production URL из панели ноды Trigger (после Publish)
Как открыть доступ Toggle Available in MCP на каждом workflow Publish workflow с Trigger + tool-нодами
Типичный кейс "Собери в n8n воронку лидов по моему промпту" "Один tool: создать лид в CRM с полями из чата"
Итоговый вердикт: Берите instance-level, если Cursor - ваш "пульт" над многими workflow. Берите MCP Server Trigger, если нужен один стабильный API-tool для команды или продакшена без лишних tools в списке.

Сверьте версию n8n (для MCP часто указывают минимум 2.18.4; UI Connect a client - с 2.33.0). Self-hosted работает, если Cursor видит домен; за proxy с 2.36.0 добавьте MCP-заголовки в allowlist.

Соберите workflow с MCP Server Trigger и production URL

Делайте: проектируйте Trigger как мини-сервис с явными tools. Не делайте: не отдавайте Cursor Test URL после отладки - для постоянной работы нужен Production URL после Publish.

Схема Trigger-path:
MCP Server Trigger → Call n8n Workflow Tool (sub-workflow) → Execute Workflow Trigger → бизнес-ноды (CRM, Telegram, Sheets)
  1. Создайте новый workflow и добавьте ноду MCP Server Trigger (транспорт SSE или streamable HTTP; stdio для Trigger не поддерживается).
  2. Настройте auth: None только в песочнице; для прода - Bearer или Header и те же значения в headers Cursor.
  3. Подключите tools: к выходу Tools добавьте Call n8n Workflow Tool (в доках также Custom n8n Workflow Tool) и укажите sub-workflow с Execute Workflow Trigger.
  4. Опишите tool понятным именем и description - агент в Cursor выбирает tool по тексту.
  5. Publish workflow и скопируйте Production URL из панели Trigger (не путать с instance-level /mcp-server/http).
  6. Добавьте отдельную запись в mcpServers Cursor с этим URL и Bearer при необходимости.

В queue mode направьте /mcp* на одну replica (docs n8n).

Включите instance-level MCP и отметьте workflow для Cursor

Делайте: включайте MCP на уровне инстанса один раз (нужны права owner/admin). Не делайте: не ждите tools в Cursor, пока workflow не помечен Available in MCP - без этого список будет пустым.

  1. Откройте Settings → Instance-level MCP → Enable MCP access.
  2. Выберите auth: OAuth (рекомендуется) или API key. Токен API key показывают один раз - сохраните в менеджер паролей, не в git.
  3. Connect a client → Cursor: используйте One-click setup и подтвердите redirect (удобнее ручного Bearer).
  4. Expose workflow: в меню workflow включите Available in MCP или добавьте в список Workflows enabled; с n8n 2.24.0 можно bulk-enable на уровне project/folder.
  5. Добавьте description к workflow - tool search_workflows опирается на метаданные; execute по умолчанию идет в production (published) версию.

Редактирование workflow через MCP - с n8n 2.13.0; на платежных цепочках сначала тест на копии.

Настройте n8n mcp cursor: mcp.json, OAuth и лимит tools

Делайте: храните конфиг либо глобально в ~/.cursor/mcp.json, либо в проекте .cursor/mcp.json (как в документации Cursor). Не делайте: не включайте одновременно official instance MCP и community n8n-mcp (stdio, документация нод) без явной нужды - список tools раздувается.

Ручной фрагмент для instance-level с API key (OAuth one-click может обойтись без headers):

{
  "mcpServers": {
    "n8n": {
      "type": "streamable-http",
      "url": "https://<your-n8n-domain>/mcp-server/http",
      "headers": {
        "Authorization": "Bearer <YOUR_N8N_MCP_TOKEN>"
      }
    }
  }
}

Local: http://localhost:5678/mcp-server/http при Cursor на той же машине. После правок - перезапуск Cursor. Лишние enabled tools (в форуме упоминают порог ~40 как предупреждение) отключайте в Customize.

Подключите Call n8n Workflow Tool: один сценарий = один MCP-tool

Делайте: выносите тяжелую логику в sub-workflow с Execute Workflow Trigger, а в Trigger-workflow оставьте тонкий tool-слой. Не делайте: не дублируйте десятки нод как отдельные tools без необходимости - агент путается, растет шум.

Sub-workflow на Execute Workflow Trigger принимает поля; Call n8n Workflow Tool мапит параметры. Один tool = одно действие ("create_lead") - проще аудит в Executions.

Проверьте подключение и прогоните тестовый запрос в Agent

Делайте: проверяйте и Cursor, и Executions в n8n одним коротким запросом. Не делайте: не считайте зеленый статус MCP достаточным, если workflow не выполнился в n8n.

Workflow проверки:
Cursor Agent → вызов tool / search_workflows → подтверждение в чате → новая запись в Executions n8n → сверка входных данных
  1. Откройте Agent и попросите вызвать exposed workflow или tool Trigger.
  2. Сверьте Executions в n8n со статусом в чате.

Устраните типичные сбои: 401, пустые tools, proxy

Делайте: идите по чеклисту сверху вниз. Не делайте: не публикуйте Bearer в чат, скриншоты и репозиторий.

  • 401 Unauthorized: неверный или устаревший Bearer; MCP отключен (N8N_DISABLED_MODULES=mcp на self-host); auth на Trigger не совпадает с headers в Cursor.
  • Пустой список tools: workflow не Available in MCP; Trigger не опубликован; tools выключены в Customize Cursor.
  • Insufficient permissions: MCP access не включен admin-ом; пользователь без прав на workflow.
  • Proxy / CORS: добавьте MCP-заголовки в allowlist с n8n 2.36.0.
  • Queue mode: один replica на /mcp*.
  • Claude Desktop vs Cursor: Claude часто идет через mcp-remote / supergateway; Cursor - native streamable-http или one-click из n8n.
  • Community n8n-mcp: другой продукт (stdio, доки); для официального сценария не обязателен.
  • Test vs production: для Cursor в проде - production URL Trigger; test только при отладке.

Что делать дальше

Зафиксируйте режим в README, урежьте exposed workflow, включите алерт на failed Executions. No-code без сервера - на курсе Make.com и вайбкодинга (MCP + публикация).

Частые вопросы

Чем MCP Server Trigger отличается от instance-level MCP в n8n?

Trigger отдает tools только из одного опубликованного workflow и свой webhook URL. Instance-level дает один endpoint на инстанс, центральную auth и expose через Available in MCP. Выберите Trigger для одного бизнес-tool, instance - для каталога workflow из IDE.

Какой URL давать Cursor: test или production?

Для постоянной работы Cursor укажите production URL Trigger после Publish. Test URL используйте только при отладке Listen for Test Event. Instance-level всегда использует /mcp-server/http на вашем домене n8n.

Можно ли подключить self-hosted n8n к Cursor MCP?

Да, если инстанс доступен из сети, где запущен Cursor: HTTPS на домене или local http по примерам n8n. Проверьте reverse proxy, заголовки MCP с версии 2.36.0 и что модуль MCP не отключен переменной окружения.

Почему Cursor показывает 401 при вызове n8n?

Сгенерируйте новый API key MCP, обновите Bearer в mcp.json, убедитесь что Instance-level MCP включен. Для Trigger сверьте схему auth на ноде и headers в Cursor символ в символ.

Почему список tools пустой?

Включите Available in MCP на workflow или опубликуйте Trigger-workflow. В Customize Cursor проверьте, что tools сервера n8n не отключены. Урежьте число enabled tools, если клиент предупреждает о лимите.

Нужен ли npm-пакет n8n-mcp для официального сценария?

Нет. Встроенный MCP n8n использует HTTP endpoint инстанса или Trigger URL. Community n8n-mcp - отдельный stdio-сервер для документации нод; подключайте только если осознанно нужен этот режим.

Как подключить n8n к cursor mcp через OAuth без ручного JSON?

В n8n откройте Instance-level MCP → Connect a client → Cursor → One-click setup, подтвердите redirect в браузере. Ручной mcp.json с Bearer оставьте для CI или когда OAuth недоступен на вашем тарифе или политике SSO.
