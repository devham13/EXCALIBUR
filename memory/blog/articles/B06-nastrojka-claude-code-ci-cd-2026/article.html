Claude Code в CI/CD обещает авто-ревью и правки в merge request, но без схемы интеграции job падает на секретах, лишних tools или бесконечном agent loop. Headless Claude Code – это запуск `claude -p` без чата: один прогон, exit code для пайплайна. Ниже – выбор между GitHub Action и bare CLI, настройка секретов, минимальные workflow для GitHub Actions и GitLab CI, guardrails и чеклист перед продакшеном. После гайда вы соберёте тестовый job и ограничите риски.

TL;DR / Быстрый инсайт: Для GitHub-only автоматизации берите `anthropics/claude-code-action@v1` и `/install-github-app`. Для Jenkins, GitLab или кастомного JSON – `claude --bare -p` с `ANTHROPIC_API_KEY`. В CI всегда ставьте `--permission-mode dontAsk`, `--allowedTools`, `--max-turns` и job timeout. GitLab-интеграция на сентябрь 2026 – beta. Не запускайте agent на untrusted PR через `pull_request_target`.

CI/CD – конвейер тестов и деплоя при каждом push. Claude Code – CLI-агент, который читает repo и вызывает tools (Bash, Edit). В пайплайне – headless, без чата. MCP расширяет агента в IDE; в CI для стабильности берут `--bare`. Локально – MCP в Cursor; фон – n8n с ИИ-агентами.

1. Выберите путь: headless `claude -p` или GitHub Action

Два входа в claude code ci cd: GitHub Action или headless CLI в shell-step.

Критерий `claude -p` в job `anthropics/claude-code-action@v1`
Setup install script + secret в env `/install-github-app` или ручная GitHub App
Триггер любой CI (GitHub, GitLab, Jenkins) GitHub events + `@claude` или `prompt` в workflow
Контекст PR checkout + gh CLI вручную comments, commits, PR – встроено
Воспроизводимость `--bare` + явные flags `claude_args` passthrough
Когда выбирать multi-CI, JSON-отчёты, свой orchestrator PR/issue automation только на GitHub
Workflow выбора:
Нужен только GitHub и ревью в PR → Action. Нужен GitLab, Jenkins или свой JSON-pipeline → headless `--bare -p`.

Делайте: зафиксируйте один путь на репозиторий, не смешивайте Action и bare CLI в одном job без причины. Не делайте: ставить Action там, где CI – GitLab или on-prem Jenkins – Action не заменит headless.

2. Настройте секреты и аутентификацию

API key – пароль для Anthropic API. OAuth – подписка Pro/Max/Team. В `--bare` нужен `ANTHROPIC_API_KEY`, не OAuth login.

  1. Шаг 1: Создайте API key в консоли Anthropic или получите org-ключ у админа.
  2. Шаг 2: GitHub: Settings → Secrets → `ANTHROPIC_API_KEY`. GitLab: Settings → CI/CD → Variables, включите Mask variable.
  3. Шаг 3: Для OAuth-сценария Action: локально `claude setup-token`, сохраните `CLAUDE_CODE_OAUTH_TOKEN` в secrets (привязан к одной подписке).
  4. Шаг 4: Enterprise: рассмотрите OIDC/WIF (Bedrock, Vertex) – короткоживущие токены вместо long-lived key в repo.
  5. Шаг 5: Добавьте `CLAUDE.md` в корень репозитория – правила review и стиль правок для стабильного поведения в CI.

Делайте: masked secrets и отдельный service account key на репозиторий. Не делайте: коммитить ключи в YAML или логировать env в echo.

3. Соберите GitHub Actions workflow

Quick path: `/install-github-app` (admin repo, `gh auth login`). Без `prompt` job ждёт `@claude`; с `prompt` – automation по триггеру.

name: Claude review
on:
  pull_request:
    types: [opened, synchronize]
jobs:
  claude:
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      id-token: write
    steps:
      - uses: actions/checkout@v4
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: |
            Review this PR. List blockers only.
          claude_args: '--max-turns 8 --allowedTools Read,Grep'

Triggering user – write access; bots отклоняются. Делайте: минимальные permissions. Не делайте: `pull_request_target` + agent на fork diff.

4. Запустите headless job в любом CI

Универсальный шаг для claude code headless: install script, PATH, bare mode, JSON для cost tracking.

  1. Шаг 1: `curl -fsSL https://claude.ai/install.sh | bash` и export `PATH="$HOME/.local/bin:$PATH"`.
  2. Шаг 2: Экспортируйте `ANTHROPIC_API_KEY` из masked variable.
  3. Шаг 3: Запустите `claude --bare -p "Your task" --permission-mode dontAsk --allowedTools "Read" --output-format json`.
  4. Шаг 4: Проверьте exit code: 0 – успех, non-zero – fail job.
  5. Шаг 5: Парсите JSON: поле `total_cost_usd` – оценка spend на клиенте; stdin через pipe ограничен 10 MB.

`--bare` без hooks/MCP/CLAUDE.md – одинаковый run. Делайте: `--allowedTools "Read"`, расширяйте после тестов. Не делайте: широкий tool-list с `dontAsk` сразу.

5. Настройте GitLab CI job (beta)

GitLab CI – beta (12.09.2026). Образ `node:24-alpine3.21`, masked `ANTHROPIC_API_KEY`, для MR – `CI_JOB_TOKEN` или PAT.

claude_review:
  image: node:24-alpine3.21
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
  script:
    - curl -fsSL https://claude.ai/install.sh | bash
    - export PATH="$HOME/.local/bin:$PATH"
    - claude -p "Summarize MR risks" --permission-mode acceptEdits
        --allowedTools "Bash Read Edit Write mcp__gitlab"
        --max-turns 10

Делайте: `rules` только на trusted branches и web/MR triggers. Не делайте: обещать команде GA-стабильность beta-фич без pin версии CLI.

6. Ограничьте риски: turns, budget, timeout

Без cap agent loop съедает лимиты API. Guardrails:

  • `--max-turns N` – stop turns; ошибка при превышении
  • `--max-budget-usd X` – cap spend (v2.1.217+)
  • Job timeout и `concurrency` – один run на PR
  • `--permission-mode dontAsk` + явный `--allowedTools`
  • Human review перед merge; rollback plan
  • Permission denied в логах – сузить tools
  • Отдельный key на repo; OIDC вместо long-lived keys
  • Не unlimited turns на публичном fork
  • Bot loop prevention в Action
  • Masked secrets; не echo env в логах

Делайте: `--output-format json` и алерт при `total_cost_usd` выше порога. Не делайте: unlimited turns на публичном форке.

7. Проверьте run и пройдите чеклист prod

Сбои: 401 (secret), permission denied (tools), timeout (turns/prompt), non-zero exit при blockers – норма, если policy так задана.

  1. Шаг 1: Тестовый workflow на internal branch без fork.
  2. Шаг 2: Сверьте exit code и артеfacts/logs job.
  3. Шаг 3: Проверьте JSON cost и сравните с `--max-budget-usd`.
  4. Шаг 4: Убедитесь, что bot не отвечает сам себе в comment loop.
  5. Шаг 5: Задокументируйте в README repo: триггеры, secrets, лимиты.

Оркестрация рядом с CI – на курсе Make.com.

Частые вопросы

Как запустить Claude Code в GitHub Actions?

Локально выполните `/install-github-app` или добавьте GitHub App вручную. Сохраните `ANTHROPIC_API_KEY` в secrets. В workflow укажите `anthropics/claude-code-action@v1`, `prompt` для automation или ждите `@claude` в interactive mode. Задайте `claude_args` с `--max-turns` и `--allowedTools`.

Что такое headless режим Claude Code?

Это `claude -p "задача"` без интерактивного чата. Агент один раз выполняет loop и завершается с exit code 0 или ошибкой – CI читает код как результат теста. Для пайплайнов добавляйте `--bare` и `--output-format json`.

Чем `--bare` отличается от обычного `-p`?

`--bare` пропускает hooks, skills, plugins, MCP и CLAUDE.md. Run быстрее и одинаковее. Нужен `ANTHROPIC_API_KEY` в env; OAuth login в bare не работает. Для scripted CI это рекомендованный режим.

Безопасно ли Claude Code в CI/CD?

Да при least-privilege: `--allowedTools`, `--permission-mode dontAsk`, caps `--max-turns` и `--max-budget-usd`, job timeout, write-access check Action, без `pull_request_target` на untrusted diff. Human review перед merge обязателен.

OAuth или API key в CI?

Для headless `--bare` – API key или OIDC/WIF в enterprise. OAuth token (`CLAUDE_CODE_OAUTH_TOKEN`) подходит для Action при подписке Pro/Max/Team, но привязан к одному аккаунту. Org-wide CI обычно на API key или cloud provider без long-lived secrets в repo.

GitLab поддерживается?

Да, через job в `.gitlab-ci.yml` по beta-доке: install script, masked `ANTHROPIC_API_KEY`, `--allowedTools` с `mcp__gitlab` при необходимости. Укажите `rules` под MR и не смешивайте с untrusted fork без изоляции secrets.

Как контролировать стоимость run?

Задайте `--max-turns`, `--max-budget-usd`, timeout job и concurrency. Используйте `--output-format json`, читайте `total_cost_usd`, алертируйте при превышении порога. Начинайте с узкого prompt и минимального набора tools.
