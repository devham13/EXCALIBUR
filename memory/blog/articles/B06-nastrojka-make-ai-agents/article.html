1. Определите, когда нужен агент, а не линейный сценарий

Линейный сценарий – фиксированная цепочка: A всегда ведёт в B. Агент подходит, когда вход разный, а решение зависит от контекста: triage заявок, квалификация лидов, черновик ответа с проверкой регламента.

Тип automation Когда использовать Пример
Standard scenario Одинаковая логика для одинакового входа Синхрон CRM и Google Sheets
Scenario + AI app Фиксированные шаги + AI-текст Перевод или краткое summary
Scenario + AI Agent Суждение, выбор tools, разный I/O Маршрутизация заявок, lead research

Делайте: один сквозной кейс (triage из Webhook или Slack). Не делайте: отдавать агенту чувствительные финансы, юридические решения и данные без human-in-the-loop – так рекомендует документация Make.

2. Создайте сценарий, триггер и модуль Run an agent

Схема workflow:
Trigger (Webhook / Slack / Gmail) → Make AI Agent (New) > Run an agent → Tools (модули / scenario / MCP) → Structured output → следующий модуль (CRM, уведомление)
  1. Шаг 1: Create scenario. В Make нажмите Create a new scenario. На Free – до 2 active scenarios и минимум 15 минут между scheduled runs; учитывайте это для prod.
  2. Шаг 2: Добавьте trigger. Webhooks – Custom webhook для формы сайта; Slack – New event; Gmail – Watch emails. Сохраните тестовый bundle для Run once.
  3. Шаг 3: Вставьте Make AI Agent (New) > Run an agent сразу после триггера или после фильтра, который отсекает спам.
  4. Шаг 4: Connection. Выберите Make's AI Provider (доступен на всех тарифах) или custom provider (OpenAI, Claude, Gemini – только paid; tokens платите провайдеру).
  5. Шаг 5: Создайте connection по подсказке мастера и сохраните сценарий в черновике – без этого Chat-тест не заработает.

Делайте: filter до агента, чтобы не тратить credits на мусор. Не делайте: путать старый Make AI Agents и новый модуль на canvas от февраля 2026.

3. Настройте Instructions, Input и лимиты выполнения

Instructions – это system prompt: роль, цель, шаги, формат ответа и запреты. Пример для triage: "Ты диспетчер заявок. Классифицируй срочность, выбери tool create_lead или send_faq. Не обещай сроки и цены. Ответ – JSON с полями priority, summary, action."

В блоке Input сопоставьте поля из trigger (текст заявки, email, канал). Для диалога включите Conversation ID и Maximum conversation history – агент помнит контекст в рамках одной беседы.

Step timeout по умолчанию – 300 секунд (5 минут): если tool завис, run оборвётся. Agent nesting – только один уровень: sub-agent не может содержать ещё одного sub-agent; для глубины используйте Call a scenario.

Делайте: явно перечислите, что агент не делает (удаление, оплата, юридические формулировки). Не делайте: prompt на три страницы – модель теряет фокус и чаще ошибается в выборе tools.

4. Подключите tools: модули, сценарии и MCP

Tools – "руки" агента. На MVP хватит 2-3 штук; каждый вызов добавляет credits.

  • Module tool – один шаг (Slack message, Google Sheets add row). Быстро для простых действий.
  • Call a scenario – цепочка с фильтрами и Return outputs. Включите On-demand, чтобы агент вызывал сценарий по необходимости.
  • Add MCP – внешние серверы через MCP; выберите минимальный набор tools, иначе растут tokens.
  • Sub-agent – второй Run an agent как tool; помните про лимит в один уровень вложенности.

Сценарий-tool обязан заканчиваться модулем Return outputs – иначе агент не получит структурированный результат. Module vs scenario: модуль – один click; scenario – multi-step с ветвлением.

Делайте: понятные имена и descriptions tools ("create_crm_lead", не "tool1"). Не делайте: вешать 10+ tools "на будущее" – агент путается, растёт счёт.

5. Добавьте Knowledge (RAG) и протестируйте в Chat и Reasoning

Knowledge хранится в RAG vector database. Форматы: JSON, TXT, CSV, PDF. Загрузка PDF/DOCX стоит 1 credit/operation + 10 tokens/page + embedding при Make's AI Provider. Для частых обновлений FAQ заведите отдельный scenario с Knowledge app вместо ручной перезаливки файлов.

  1. Шаг 6: Add knowledge в Run an agent – upload регламента или brand guide.
  2. Шаг 7: Откройте Chat на canvas – задайте 3-5 типовых заявок, как в prod.
  3. Шаг 8: Run once с сохранённым bundle из trigger – проверьте Output.
  4. Шаг 9: History → Reasoning – пошаговое мышление агента для отладки; отключайте tools по одному, чтобы найти сбой.

Тарификация (open beta): Run an agent с Make's AI Provider – 1 credit/operation + tokens; каждый tool в Chat – +1 credit. Custom provider – 1 credit/operation, tokens платите провайдеру. Billing с 27 августа – в credits.

6. Пройдите чеклист перед включением в production

Перед переключением с черновика на live пройдите список – так снижаете риск сжечь credits и отправить неверный ответ клиенту.

  • Filter до Run an agent отсекает спам и пустые payload
  • Instructions содержат роль, формат JSON/text и список запретов
  • Не больше 3-5 tools на первый prod-релиз
  • Call a scenario завершается Return outputs и On-demand включён
  • MCP-tools ограничены нужным минимумом
  • Knowledge актуален; устаревший PDF хуже, чем его отсутствие
  • Step timeout 300 с достаточен или увеличен осознанно
  • Chat-тест + Run once + Reasoning пройдены на 5+ кейсах
  • После агента стоит approval (Slack/Telegram) перед CRM или отправкой клиенту
  • Logging: History сохраняется, ответственный знает, где смотреть ошибки
  • Мониторинг credits: на pricing Make – уведомления на 75% и 90% лимита

Частые вопросы

Чем Make AI Agents отличается от обычного сценария?

Агент сам выбирает tools и порядок шагов по Instructions; линейный сценарий всегда идёт по одной цепочке модулей. Для triage и квалификации лидов берите агента; для синка таблиц – classic scenario.

Нужен ли свой OpenAI ключ для агента в Make?

Нет для старта: Make's AI Provider доступен на всех тарифах. На paid подключите OpenAI, Claude или Gemini как custom provider – tokens тогда платите провайдеру, Make берёт 1 credit/operation за Run an agent.

Как добавить MCP в Make AI Agents?

В Run an agent нажмите Add MCP, создайте connection к серверу и отметьте только нужные tools. Перезапустите Chat-тест: если агент вызывает лишние MCP-tools, сузьте список в настройках модуля.

Сколько credits съедает один run агента?

Минимум 1 credit за Run an agent плюс 1 credit за каждый вызванный tool в Chat и credits по tokens при Make's AI Provider. Сверяйте расход в History и на странице credit usage для AI agents в help.make.com.

Какие файлы загружать в Knowledge?

JSON, TXT, CSV, PDF. Для FAQ, который меняется каждую неделю, соберите отдельный scenario с Knowledge app и подключите его как источник – так проще обновлять базу без ручной перезаливки PDF.

Как тестировать агента до production?

Используйте Chat на canvas, затем Run once с реальным bundle из trigger. В History откройте Output и вкладку Reasoning; отключайте tools по одному, пока не найдёте модуль, который ломает цепочку.

Можно ли вложить агента в агента?

Да, один уровень sub-agent через Add tool. Sub-agent не может содержать своего sub-agent. Для более глубокой логики соберите Call a scenario с Return outputs и включите On-demand.
