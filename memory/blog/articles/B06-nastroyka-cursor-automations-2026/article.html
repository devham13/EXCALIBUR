Cursor Automations запускают Cloud Agents в фоне: по расписанию, при открытии PR или webhook. Без настройки вы каждый раз вручную открываете чат и повторяете одни и те же инструкции. За 30–45 минут вы подключите GitHub, добавите секреты в dashboard, создадите первую Automation с правильным trigger и repo scope, прогоните Test run и прочитаете Run History. Ниже – пошаговая инструкция для маркетологов и автоматизаторов без глубокого dev-бэкграунда.

TL;DR / Быстрый инсайт: Cloud Agent – тот же облачный агент Cursor, но вы запускаете его вручную из IDE или web. Automation – тот же агент, который "просыпается" сам по событию или cron. Пять шагов в dashboard: trigger → instructions → tools → repo scope → save. Для утреннего брифа без кода выберите No repository; для PR-review – Single repository. Cron считается в UTC: 9:00 по Москве (лето) = 0 6 * * *. Секреты – только в Dashboard Secrets, не в git и не в промпте.

Trigger – "будильник или дверной звонок"; repo scope – "нужен ли агенту доступ к коду". MCP-tools подключайте после первого Test run – см. гайд MCP.

1. Выберите между Cloud Agents и Automations

Cloud Agents – на paid-планах; Start (Индия) без Automations, нужен Pro+. Billing – API pricing модели на каждый run.

Критерий Cloud Agent (ручной) Automation (event-driven)
Кто запускает Вы из IDE или cursor.com/agents Trigger: cron, GitHub, Slack, webhook и др.
Когда брать Разовая задача, эксперимент, mid-run правки Регулярный бриф, PR-review, реакция на события 24/7
Repo scope Выбираете при старте run Задаётся при создании Automation
Результат Transcript в Agents Window Run History + артефакты (комментарий PR, markdown)

Делайте: для повторяющихся сценариев сразу Automation. Не делайте: вручную дублировать один prompt каждое утро – проще один раз настроить scheduled trigger.

2. Подготовьте среду: план, GitHub и Secrets

Перед созданием Automation проверьте три опоры: paid-план, подключённый GitHub (если нужен PR-сценарий) и секреты в dashboard.

  1. Шаг 1: Убедитесь, что тариф Pro или выше; откройте Cloud Agents setup (dashboard: cursor.com/dashboard/cloud-agents) и задайте spend limit.
  2. Шаг 2: Подключите GitHub, GitLab или Bitbucket в настройках Cursor – для PR-review без SCM trigger не заработает.
  3. Шаг 3: Dashboard → Cloud Agents → вкладка Secrets. Добавьте Runtime Secret для токенов (значение скрыто в transcript и commits).
  4. Шаг 4: Не кладите API-ключи в .cursor/environment.json – в этом файле поля secrets нет; порядок среды: файл в репо → personal saved → team saved.
Repo scope Когда выбирать Ограничение
No repository Slack, cron-бриф, webhook, Linear Не правит код и не открывает PR
Single repository Review и правки в одном репо Одна ветка, один проект
Multi-repo environment Задача на нескольких репозиториях Настройка через cloud environment

Делайте: минимум секретов с понятными именами (GITHUB_TOKEN, SLACK_WEBHOOK). Не делайте: вставлять ключи в instructions – они попадут в Run History.

3. Создайте первую Automation пошагово

Откройте cursor.com/automations/new или Agents Window → Automations → New. Для обучения берите blank, не шаблон Marketplace – так видите все поля.

Workflow создания:
Trigger → Instructions → Tools (минимум) → Repo scope → Save & Activate → Test run → Run History
  1. Шаг 1: Задайте имя Automation и выберите trigger (ниже – таблица).
  2. Шаг 2: Напишите instructions: формат выхода (markdown-бриф или комментарий PR), запреты (no auto-merge), правило "comment vs silence".
  3. Шаг 3: Включите только нужные tools: Comment on PR, Send to Slack, MCP – по задаче.
  4. Шаг 4: Выберите repo scope: для утреннего брифа – No repository; для PR – Single repository с target repo.
  5. Шаг 5: Save → Activate → Test run. Проверьте timestamp в Run History и артефакт (markdown или комментарий).
  6. Шаг 6: Для webhook: URL и API key появляются только после Save – скопируйте их до продакшена.

Сценарий A: Scheduled, No repository – бриф в Run History. Сценарий B: GitHub PR + Single repo, Comment on PR, без auto-merge. Альтернатива – skill /automate; для обучения blank надёжнее.

4. Настройте trigger и переведите cron UTC в MSK

Automation может иметь несколько triggers – запуск при срабатывании любого из них. Для Slack и cron Cursor по умолчанию не подключает репозиторий; для GitHub/GitLab triggers repo обязателен.

Trigger Repo нужен? Типичная задача
Scheduled (cron) Нет (по умолчанию) Утренний бриф, дайджест
GitHub PR opened/pushed Да Code review, lint-комментарии
Slack message Нет Ответ в public-канале (без фильтра – только top-level)
Webhook HTTP POST Зависит от prompt CRM, формы, внешние системы
Linear / PagerDuty Часто No repository Тикеты и инциденты

Cron в Automations считается в UTC. UI может показывать local time – отсюда типичная ошибка "ждал 9:00, сработало в 11:00". Для 9:00 MSK летом (UTC+3):

0 6 * * *

Делайте: после первого scheduled run сверьте timestamp в Run History с ожиданием. Не делайте: включать все tools "на всякий случай" – лишние MCP увеличивают стоимость run и шум в transcript.

5. Задайте /goal и event subscriptions для долгих задач

С 19.08.2026 Subscriptions: агенты мониторят PR, Slack и cron, auto-subscribe к своим PR и доводят CI до green. /goal – long-lived objective ("fix flaky tests, CI green") в новом чате cloud agent. Subagents – на отдельных VM; mid-run steering не обрывает агента mid-action.

Делайте: /goal для задач на часы и дни (CI green, серия PR). Не делайте: дублировать ту же цель в Automation и /goal без разделения – один канал на сценарий.

6. Прогоните Test run и устраните типичные сбои

После Activate нажмите Test run – это полноценный Cloud Agent run с billing по API pricing модели. Run History показывает transcript, время старта и ошибки.

  • Cron не в то время: пересчитайте UTC; сверьте Run History timestamp.
  • 403 / secrets: ключ не в Dashboard Secrets или имя env не совпадает с instructions.
  • PR trigger молчит: не подключён GitHub или неверный target repo.
  • Slack не видит канал: только public channels; private – недоступны.
  • Webhook пустой: Save Automation – URL появляется после сохранения.
  • Лишний billing: отключите неиспользуемые tools и MCP.

Make закрывает CRM → Telegram; Automations – фоновый агент в облаке. Связка на курсе Make.com (159+ уроков).

7. Пройдите чеклист перед продакшеном

  • Paid-план Pro+; spend limit задан в dashboard
  • GitHub подключён, если нужен SCM trigger
  • Секреты в Dashboard Secrets, не в git
  • Repo scope осознанно: No / Single / Multi
  • Instructions с форматом выхода и запретами
  • Tools – минимум под задачу
  • Cron пересчитан UTC → MSK
  • Test run успешен, артефакт на месте
  • Run History: timestamp и billing ожидаемы
  • Webhook URL скопирован после Save
  • MCP только доверенные (см. гайд MCP)

8. Что делать дальше

  1. Создайте scheduled бриф (сценарий A) и добейтесь стабильного Run History три дня подряд.
  2. Добавьте вторую Automation для PR-review (сценарий B) в test-репозитории.
  3. Подключите webhook из CRM или формы – один POST на endpoint Automation.
  4. Для долгой CI-задачи попробуйте /goal в cloud agent.
  5. Масштабируйте связку с Make – обучение по Make.com с AI-сценариями.

Частые вопросы

Как настроить cursor automations?

Откройте cursor.com/automations/new → выберите trigger → напишите instructions → включите нужные tools → задайте repo scope → Save, Activate и Test run. Результат смотрите в Run History.

Чем cloud agents отличаются от automations?

Cloud Agent вы запускаете вручную. Automation – тот же cloud agent, но старт по trigger (cron, GitHub, Slack, webhook). Runs и billing одинаковые по API pricing.

Нужен ли GitHub для брифа по расписанию?

Нет. Для cron и Slack без правок кода выберите No repository. GitHub обязателен только для source control triggers (PR opened, push).

Как работает /goal в Cursor?

Long-lived objective в новом чате cloud agent: агент держит цель до завершения (например, CI green). Pair с Custom Mode или /loop; subscriptions мониторят PR и Slack между runs.

Почему automation сработала не в 9:00 по Москве?

Cron в Automations считается в UTC. Для 9:00 MSK летом используйте 0 6 * * * или preset и сверьте timestamp первого run в Run History.

Где хранить API-ключи для Automation?

Dashboard → Cloud Agents → Secrets. Тип Runtime Secret скрывает значение в transcript. Не храните ключи в environment.json, промпте или git.

Когда webhook URL пустой?

URL и API key появляются только после Save и Activate Automation. Сохраните черновик, скопируйте endpoint, затем подключайте внешнюю систему.
