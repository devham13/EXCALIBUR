Cursor Automations запускают Cloud Agent без вашего участия: по расписанию, webhook из CRM или событию в Slack. Ручной чат каждый раз одно и то же не масштабируется. За 30–45 минут вы создадите первую Automation с cron или webhook, проверите Run History и поймёте, когда нужен репозиторий, а когда достаточно prompt и MCP. Ниже – единая настройка cursor automations для бизнеса без Senior-разработчика.

TL;DR / Быстрый инсайт: Cursor Automations – фоновые Cloud Agents по триггеру (cron, webhook, Slack, PR). Создание: trigger → prompt → tools → repo scope → Save. Для брифов без кода выберите Scheduled + No repository. Webhook URL и API key появляются только после Save. Billing: included usage, затем on-demand; задайте spend limit. Cron по Москве: community-формула CRON_TZ=Europe/Moscow – сверяйте время в Run History.

Automations вышли 5 марта 2026. Cloud Agent в чате – разовый подрядчик; Automation – смена по будильнику cron или звонку webhook. Projects – координатор с общей памятью; Automations – trigger → action. Связка с MCP и контент-заводом: B03, B05.

1. Сравните Cloud Agent, Automation, чат и Projects

Режим Когда запускается Нужен repo Для кого
Чат / Agent в IDE Вы написали prompt Опционально Разовая задача, правки кода
Cloud Agent (ручной) Вы отправили задачу в Agents Часто да PR, review, исследование
Automation Cron, webhook, Slack, PR и др. Зависит от trigger Брифы, triage, security scan
Cursor Projects Подписки на PR/Slack + schedule Да Долгий проект с памятью

Делайте: Automation для повторяющихся задач с чётким выходом (markdown-бриф, комментарий в PR). Не делайте: дублировать одну задачу в чате каждое утро – это дороже по времени и хуже по billing.

2. Подготовьте аккаунт: Pro+, on-demand и spend limit

Automations требуют Pro и выше (Start для Индии не подходит). Pro – от $20/мес; каждый run – по API pricing модели с полным контекстным окном.

  1. Шаг 1: Проверьте план в Settings → Billing: Pro, Pro Plus или Ultra.
  2. Шаг 2: Включите on-demand billing – без него фоновые runs могут не стартовать после исчерпания included usage (подтверждение на форуме Cursor).
  3. Шаг 3: Задайте spend limit с запасом ~$2 headroom – hard limit может блокировать старт run.
  4. Шаг 4: Для repo-backed сценариев подключите GitHub, GitLab или Bitbucket Cloud.
  5. Шаг 5: Токены Slack, Linear, CRM – в Dashboard Secrets, не в prompt и не в скриншотах.

Делайте: мониторить Usage после первых test runs. Не делайте: запускать десяток automations с computer use и MCP до понимания стоимости одного run.

3. Создайте первую Automation: trigger, prompt, tools, scope

Workflow настройки:
Подготовка аккаунта → cursor.com/automations/new (или /automate в Agent) → trigger → prompt → tools → repo scope → Save & Activate → Run History → масштабирование (MCP, webhook)

Создание: cursor.com/automations, Agents Window → New Automation или skill /automate. Несколько triggers на одну Automation – срабатывает любой.

Trigger Repo по умолчанию Типичный кейс
Scheduled (cron) No repository Утренний бриф, дайджест
Webhook POST No repository Заявка с сайта, Make/n8n
Slack message No repository Триаж по ключевому слову
PR opened / push Single repo обязателен Review, security scan
Linear / PagerDuty Часто no-repo Инциденты, тикеты
  1. Шаг 1: Выберите Scheduled preset "Daily" для первого теста или Webhook для интеграции с CRM.
  2. Шаг 2: Repo scope: No repository для брифа без правок кода; Single/Multi – для PR и push.
  3. Шаг 3: Prompt: формат выхода (markdown), длина, критерий готовности, явные запреты (no PR, no clone при no-repo).
  4. Шаг 4: Tools – минимум: Send to Slack только если нужен; MCP – если агент должен читать внешние данные; computer use включайте осознанно.
  5. Шаг 5: Save & Activate → откройте Run History и дождитесь статуса FINISHED.

Пример prompt для утреннего брифа без repo:

Собери бриф на русском, до 400 слов:
1) 3 главных задачи команды на сегодня (из памяти MEMORIES.md)
2) Открытые блокеры
3) Одна рекомендация по приоритету
Формат: markdown с заголовками. Не создавай PR и не клонируй репозиторий.

Делайте: один полный walkthrough на cron no-repo, затем webhook. Не делайте: включать PR creation для no-repo брифа – tool не нужен и увеличивает риск лишних действий.

4. Настройте cron: preset, CRON_TZ и Run History

Scheduled: preset или custom cron. Запуск может сдвинуться, но не раньше указанного времени. Москва – community-префикс CRON_TZ (сверяйте Run History):

CRON_TZ=Europe/Moscow 0 9 * * 1-5

09:00 пн–пт по Москве. Делайте: test на ближайшем preset. Не делайте: cron каждые 5 минут с MCP – included usage уйдёт быстро.

5. Подключите webhook: URL, API key и POST из Make/n8n

Webhook – private HTTP endpoint. URL и API key Cursor показывает только после Save automation. Внешний оркестратор (Make, n8n, CRM) шлёт POST с телом JSON и заголовком Authorization.

POST https://your-automation-endpoint.cursor.com/...
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{"lead_name": "Иван", "source": "site_form", "message": "Нужен демо-звонок"}

Make/n8n: HTTP POST + Bearer + JSON из CRM. Prompt опишите обработку полей. Webhook + MCP – на курсе Make.com. Делайте: test POST до CRM. Не делайте: светить API key – при утечке re-save или Team Owned с новым ключом.

6. Добавьте MCP, Memories и multi-repo для сложных сценариев

MCP – "розетки" для Browser, Linear, CMS (подключение). Memories пишет в MEMORIES.md – фильтруйте untrusted поля webhook. Multi-repo – для нескольких репозиториев; Team Owned переносит billing в team pool и требует новый webhook key. Делайте: MCP для брифов с памятью. Не делайте: computer use на no-repo webhook без ограничений в prompt.

7. Пройдите чек-лист безопасного запуска

  • Spend limit и on-demand включены до первого cron
  • Secrets в Dashboard, не в prompt
  • Webhook API key не в публичных репозиториях
  • No repository для задач без правок кода
  • Repo обязателен для PR/push triggers – иначе run упадёт
  • PR из fork не поддерживаются (кроме PR merged) – учитывайте open source
  • Slack triggers – только public channels
  • Memories: фильтруйте untrusted поля webhook в prompt
  • Run History: статус FINISHED и осмысленный output
  • Billing dashboard после недели pilot – скорректируйте частоту cron
  • Team Owned – перегенерировать webhook key после promote
  • Доступ к cursor.com зависит от региона и типа аккаунта – сверьте официальные docs

Ошибки: нет on-demand; webhook 401; cron не по Москве – CRON_TZ + History; fork PR не поддерживаются.

8. Что делать дальше

  1. Запустите cron no-repo бриф и зафиксируйте стоимость одного run.
  2. Добавьте webhook из Make или n8n для одной CRM-формы.
  3. Подключите MCP по гайду B03 для доступа к Linear или CMS.
  4. Для PR review – Single repo + trigger PR opened + Comment on PR.
  5. Масштабируйте на контент-завод или обучение Make + Cursor.

Частые вопросы

Чем Cursor Automations отличается от Cloud Agent в чате?

Automation стартует по trigger без вашего prompt: cron, webhook, Slack, PR. Cloud Agent в чате – разовая задача, которую вы формулируете вручную. Для повторяющихся бизнес-процессов создайте Automation; для эксперимента – чат или ручной Cloud Agent.

Нужен ли репозиторий для Automation?

Нет для cron, Slack, webhook и Linear/PagerDuty без правок кода – выберите No repository. Да для push, PR opened, CI completed и других source control triggers: подключите GitHub, GitLab или Bitbucket и укажите Single или Multi repo.

Как настроить cron по московскому времени?

В custom cron добавьте community-префикс CRON_TZ=Europe/Moscow и expression, например 0 9 * * 1-5 для 09:00 пн–пт. Save automation, дождитесь run и сверьте timestamp в Run History; при расхождении скорректируйте expression.

Сколько стоит cursor automations?

Тариф Pro от $20/мес даёт доступ к Cloud Agents; каждый run тарифицируется по API pricing модели. Included usage расходуется первым, затем on-demand. Задайте spend limit в Billing и смотрите Usage после pilot – power users часто выходят на $200+/мес суммарно.

Где взять webhook URL и API key?

Только после Save & Activate automation – Cursor покажет private endpoint и key. POST с Authorization: Bearer YOUR_API_KEY и JSON-телом. Key не публикуйте; при утечке пересоздайте через re-save или Team Owned promote.

Можно ли обойтись без GitHub?

Да для no-repo workflows: брифы, webhook из CRM, Slack triage с MCP. Для изменений кода, PR и security scan на push – подключите GitHub, GitLab или Bitbucket в настройках аккаунта.

Automations или Cursor Projects – что выбрать?

Automations – trigger → action для повторяющихся задач (бриф, webhook, review PR). Projects – long-running координатор с shared context и подписками на PR/Slack. Начните с Automations; Projects – когда нужен единый контекст на недели работы над фичей.
