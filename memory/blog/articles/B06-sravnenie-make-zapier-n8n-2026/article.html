1. Пройдите чек-лист из 4 критериев перед выбором платформы

Не начинайте с таблицы интеграций. Сначала зафиксируйте профиль нагрузки и ограничений – иначе сравнение make n8n zapier превратится в спор фанатов.

  1. Объём операций. Сколько активных сценариев, сколько шагов в одном прогоне, сколько запусков в месяц. Запишите пик (акции, сезон).
  2. 152-ФЗ и хранение данных. Есть ли ПДн граждан РФ в полях CRM, формах, логах. Нужна ли локализация на сервере в РФ.
  3. Роль ИИ. Нужны ли AI-агенты и MCP; у Make AI Agents и MCP server на всех тарифах, у n8n – AI Agent node в Cloud.
  4. Техресурс. Есть ли человек, который поднимет Docker, бэкапы и HTTPS на self-host, или команда живёт только в no-code облаке.

Эталон billing: 4 шага, 1 000 запусков/мес → Zapier ≈ 4 000 tasks (pricing), Make ≈ 4 000 credits (Router без списания), n8n ≈ 1 000 executions (n8n.io/pricing).

4. Перенесите сценарии с Make на n8n без простоя: пошаговый план

Blueprint Make – JSON модулей без connections (blueprints). В n8n нет прямого импорта: rebuild или конвертер с ручной проверкой.

Схема миграции:
Make live → Export blueprint → Rebuild/конвертер + review → Credentials в n8n → Parallel run 3–7 дней → Смена webhook URL → Отключить Make
  1. Инвентаризация. Список сценариев по критичности: revenue, support, внутренние отчёты. Начните с некритичного.
  2. Export blueprint. Make → Export blueprint → сохраните `.json` в защищённое хранилище.
  3. Rebuild в n8n. Повторите логику нодами n8n; при использовании конвертера сверьте ветки Router и фильтры построчно.
  4. Credentials. Переподключите OAuth и API-ключи в n8n (как после импорта blueprint в Make).
  5. Parallel run. 3–7 дней гоняйте оба контура; сравнивайте выходные данные в таблице или Slack-алерте на расхождение.
  6. Cutover webhooks. Переключите URL в CRM, формах, Telegram-ботах на n8n; держите rollback-URL Make ещё 48 часов.
  7. Decommission. Отключите Make-сценарий, архивируйте blueprint и зафиксируйте дату в runbook.

Делайте: parallel run и тест без боевых ПДн. Не делайте: cutover без rollback URL.

5. Проверьте compliance для РФ: чек-лист ПДн, логов и subprocessors

Это не юридическая консультация. При ПДн в облаке EU/US нужна оценка с юристом; self-host в РФ даёт контроль infra, но не снимает процессы backup и доступа.

  • Карта потоков: откуда ПДн входят (форма, CRM, мессенджер) и какие поля уходят в сценарий.
  • Где хранятся execution logs n8n / history Make – срок retention и доступ сотрудников.
  • Subprocessors: OpenAI, Google, Telegram – перечень в договорах и политике конфиденциальности.
  • Шифрование HTTPS на webhook и admin UI self-host.
  • Encryption key n8n в prod (переменные окружения, не в git).
  • Разделение prod/test credentials; test без боевых ПДн.
  • Backup базы n8n (Postgres) и тест восстановления раз в квартал.
  • RBAC: кто может редактировать сценарии с доступом к CRM.
  • Аудит экспорта blueprint – JSON может содержать mapped values.
  • Договор с хостингом VPS в РФ: jurisdiction и SLA.
  • Если данные только в Make AWS EU / n8n Frankfurt – зафиксируйте решение юриста письменно.
  • План реагирования на утечку: контакт, блокировка API-ключей, ротация webhook secret.

Делайте: эскалируйте спорные кейсы юристу до cutover. Не делайте: считать "EU = автоматически OK для 152-ФЗ" без оценки категорий данных.

Частые вопросы

Make или n8n для малого бизнеса в РФ?

Откройте Free Make без DevOps и при умеренной нагрузке. n8n self-host – при ПДн и сервере в РФ; n8n Cloud – EU + trial 14 дней.

Работает ли Zapier из России в 2026?

Проверьте ToS: hosting в США, формулировки про sanctions, оплату. Для новых контуров в РФ планируйте Make или n8n, а Zapier оставьте только при уже легальном доступе и оплате.

Почему n8n часто дешевле Make на больших объёмах?

Сравните execution против credits на эталоне 4 шага × 1 000 runs: n8n = 1 000 списаний, Make ≈ 4 000 credits. На self-host CE нет лимита runs в лицензии – платите infra отдельно.

Можно ли перенести сценарий Make одной кнопкой в n8n?

Нет. Сделайте Export blueprint, затем rebuild или конвертер с ручной проверкой; credentials подключите заново в n8n.

Где хранятся данные Make и n8n Cloud?

Make – AWS EU/NA (pricing). n8n Cloud – EU Frankfurt (n8n pricing). Self-host – там, где вы развернули инстанс.

Что с 152-ФЗ при облачной автоматизации?

Составьте карту ПДн и согласуйте с юристом; self-host – инженерный шаг, не замена процессам без DPO.

Нужен ли Zapier в 2026?

Только если процессы уже на Zaps и есть устойчивая оплата/доступ. Иначе начните с Make или n8n и не размножайте зависимость от US-only стека.
