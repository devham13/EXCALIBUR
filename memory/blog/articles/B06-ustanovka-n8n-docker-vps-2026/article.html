Telegram и CRM шлют webhook только на публичный HTTPS, а n8n Cloud упирается в лимиты runs. Self-hosted n8n на VPS (виртуальный сервер 24/7) держит сценарии и пароли у вас, в том числе на российском хостинге. Ниже – установка n8n на VPS: Docker Compose, PostgreSQL 18, external runners, Caddy и правильные N8N_WEBHOOK_URL. Вы поднимете панель по https и базу под ИИ-агентов в n8n.

TL;DR / Быстрый инсайт: Production-стек: VPS от 4 GB RAM и 2 vCPU, Docker Compose, Postgres 18, n8n stable 2.42.6 (pin версии, не latest), sidecar n8nio/runners, reverse proxy на 443, n8n слушает только 127.0.0.1:5678. Обязательны N8N_ENCRYPTION_KEY, N8N_WEBHOOK_URL и N8N_PROXY_HOPS=1. Бэкапьте .env, том Postgres и /home/node/.n8n. Схема: DNS → Caddy:443 → n8n:5678 → Postgres + runners.

n8n – конструктор автоматизаций из блоков (нод); webhook – входящий вызов на URL, который запускает workflow. Docker Compose поднимает n8n, Postgres и runners одним файлом. На 10.10.2026 docs n8n рекоменуют Compose для self-host; CE бесплатна, Cloud Starter – от 20 €/мес за 2 500 executions.

1. Выберите VPS, домен и сравните с n8n Cloud

Делайте: берите минимум 4 GB RAM и 2 vCPU (официальный минимум под Compose и sandbox/runners). Ubuntu 24.04 LTS или Debian 12 – типовой выбор в RU-гайдах. Привяжите домен A-записью на IP VPS, откройте в firewall только 80 и 443. Порт 5678 (веб-интерфейс n8n) наружу не публикуйте – только localhost + прокси.

Не делайте: ставить n8n на 2 GB RAM "на авось" – при Code node и runners получите OOM; docs советуют увеличить RAM или NODE_OPTIONS=--max-old-space-size, но проще сразу взять запас.

2. Установите Docker и подготовьте каталог /opt/n8n

На чистом Ubuntu 24.04 установите Docker Engine и плагин Compose по официальной инструкции Docker. Проверка: команда docker compose version должна ответить версией v2, не legacy docker-compose.

  1. Шаг 1: Создайте каталог. sudo mkdir -p /opt/n8n && sudo chown $USER:$USER /opt/n8n && cd /opt/n8n
  2. Шаг 2: Сгенерируйте секреты. N8N_ENCRYPTION_KEY (32+ символа, openssl rand -hex 32), пароль Postgres, N8N_RUNNERS_AUTH_TOKEN (openssl rand -hex 32). Сохраните их в менеджере паролей – смена ключа после запуска ломает расшифровку credentials в n8n.
  3. Шаг 3: Создайте файл .env (права chmod 600). Пример без реальных секретов:
N8N_VERSION=2.42.6
POSTGRES_USER=n8n
POSTGRES_PASSWORD=ЗАМЕНИТЕ_СИЛЬНЫЙ_ПАРОЛЬ
POSTGRES_DB=n8n
N8N_ENCRYPTION_KEY=ЗАМЕНИТЕ_HEX_32
N8N_RUNNERS_AUTH_TOKEN=ЗАМЕНИТЕ_HEX_32
GENERIC_TIMEZONE=Europe/Moscow
N8N_HOST=n8n.example.ru
N8N_PROTOCOL=https
N8N_WEBHOOK_URL=https://n8n.example.ru/
N8N_PROXY_HOPS=1

Делайте: pin версию образа через N8N_VERSION=2.42.6 (stable на 10.10.2026). Не делайте: коммитить .env в git или вставлять ключи в скриншоты – только плейсхолдеры в документации.

3. Соберите docker-compose.yml и запустите PostgreSQL, n8n и runners

Ориентир – официальный репозиторий n8n-hosting, вариант withPostgres: Postgres 18 с PGDATA=/var/lib/postgresql/data, healthcheck pg_isready, образ docker.n8n.io/n8nio/n8n. С n8n 2.0 task runners включены по умолчанию; в external mode добавьте контейнер n8nio/runners той же версии, что и n8n.

Workflow запуска:
docker compose config → docker compose up -d → docker compose ps → curl http://127.0.0.1:5678 → owner в UI → тест webhook
  1. Шаг 4: Положите docker-compose.yml рядом с .env. Укажите DB_TYPE=postgresdb, DB_POSTGRESDB_HOST=postgres, том для /home/node/.n8n (ключи шифрования и assets даже при Postgres), depends_on с condition: service_healthy.
  2. Шаг 5: Добавьте сервис runners. N8N_RUNNERS_MODE=external на n8n, broker на 0.0.0.0:5679, у runners – N8N_RUNNERS_TASK_BROKER_URI=http://n8n:5679 и тот же N8N_RUNNERS_AUTH_TOKEN.
  3. Шаг 6: Запустите стек. docker compose up -d. Логи: docker compose logs -f n8n. Ошибки миграции Postgres 18 на старом volume – отдельный кейс: major upgrade требует pg_dumpall по docs, не удаляйте том вслепую.
  4. Шаг 7: Проверьте локально. На VPS: curl -I http://127.0.0.1:5678. Должен отвечать n8n до настройки HTTPS. Создайте первого пользователя (owner) в браузере через SSH-туннель или временно, пока нет proxy.
  5. Шаг 8: Зарегистрируйте CE. Settings → Usage: бесплатная регистрация по email открывает folders и debug in editor – полезно до продакшена.

Скопируйте базу из n8n-hosting/withPostgres и добавьте сервис runners, bind 127.0.0.1:5678 и переменные из .env. Ключевые строки для n8n:

image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
ports: ['127.0.0.1:5678:5678']
environment:
  DB_TYPE: postgresdb
  N8N_RUNNERS_MODE: external
  N8N_RUNNERS_AUTH_TOKEN: ${N8N_RUNNERS_AUTH_TOKEN}

Делайте: держите версию runner = версии n8n. Не делайте: использовать SQLite в prod – только Postgres; SQLite в docs оставлен для локальных тестов.

4. Настройте Caddy, HTTPS и URL для вебхуков

Reverse proxy – "швейцар" перед n8n: принимает HTTPS на 443 и проксирует на 127.0.0.1:5678. Caddy сам получает сертификат Let's Encrypt, если DNS уже указывает на сервер и порт 80 доступен с интернета.

Установите Caddy на хост (не обязательно в том же compose). Минимальный Caddyfile:

n8n.example.ru {
  reverse_proxy 127.0.0.1:5678
}

После reload Caddy откройте https://n8n.example.ru. В .env уже должны быть N8N_HOST, N8N_PROTOCOL=https, N8N_WEBHOOK_URL=https://n8n.example.ru/ (со слэшем в конце по docs). WEBHOOK_URL без префикса N8N_ – deprecated с 2.35.0.

За одним прокси-слоем выставьте N8N_PROXY_HOPS=1 и убедитесь, что Caddy передаёт X-Forwarded-For и X-Forwarded-Proto – иначе n8n генерирует http-ссылки и ломает secure cookie (типичная ошибка 502 или бесконечный редирект).

  1. Шаг 9: Smoke-test webhook. Создайте workflow с Webhook node, скопируйте Production URL, отправьте GET/POST из браузера или curl с другого устройства – должен прийти execution.
  2. Шаг 10: Подключите внешний сервис. Telegram Bot API или CRM webhook – только после зелёного HTTPS. Test URL в n8n для отладки, Production – для боевого триггера.

Делайте: дождитесь распространения DNS (от минут до суток) перед выводом в prod. Не делайте: обещать "15 минут до prod", если домен только что создан.

5. Пройдите чеклист продакшена, бэкап и обновление

Перед боевыми интеграциями пройдите список:

  • Зафиксирована версия образа n8n и runners в .env, не latest.
  • N8N_ENCRYPTION_KEY сохранён offsite вместе с .env.
  • Postgres volume и n8n_data бэкапятся по cron (pg_dump + архив тома или snapshot VPS).
  • Порт 5678 привязан к 127.0.0.1, снаружи только 443.
  • N8N_WEBHOOK_URL совпадает с публичным https-доменом.
  • N8N_PROXY_HOPS=1 при одном reverse proxy.
  • Healthcheck postgres зелёный в docker compose ps.
  • Runners в логах без auth errors.
  • Owner-аккаунт с сильным паролем, лишние тестовые workflow удалены.
  • Обновление: docker compose pull, docker compose down, docker compose up -d – без смены encryption key.
  • Major Postgres – только по официальной миграции (dump/restore).
  • Документирована дата и версия перед каждым pull.

Minor-обновление: бэкап → docker compose pull → up -d. При OOM увеличьте RAM или упростите Code node. Дальше – ИИ-агенты в n8n, MCP в Cursor; no-code без DevOps – курс Make на kv-ai.ru.

Частые вопросы

Сколько RAM нужно для n8n на VPS?

Официальный минимум для Docker Compose – 4 GB RAM и 2 vCPU. Если в workflow много Code node и external runners, следите за памятью в docker stats; при OOM увеличьте тариф VPS или уменьшите параллельные executions.

Можно ли n8n бесплатно на своём VPS?

Да: Community Edition без платы за лицензию. Вы платите только хостинг и внешние API. Регистрация CE по email в Settings unlock часть удобств редактора – это бесплатно.

Почему вебхуки не работают без HTTPS?

Внешние сервисы вызывают публичный URL. Задайте N8N_WEBHOOK_URL=https://ваш-домен/, поднимите reverse proxy на 443 и проверьте Production URL в Webhook node curl-ом с интернета.

SQLite или PostgreSQL?

Для prod – только PostgreSQL через DB_TYPE=postgresdb. SQLite подходит для быстрого локального теста, не для данных клиентов и 24/7 webhook.

Зачем отдельный контейнер n8nio/runners?

С n8n 2.0 Code node выполняется через task runners в изолированном окружении. В external mode runner – отдельный контейнер; версия образа runners должна совпадать с версией n8n.

Что обязательно бэкапить?

Файл .env с N8N_ENCRYPTION_KEY, дамп Postgres и volume /home/node/.n8n. Без ключа восстановить сохранённые credentials в n8n нельзя.

Как обновить n8n без потери данных?

Сделайте бэкап, выполните docker compose pull и docker compose up -d. N8N_ENCRYPTION_KEY не меняйте. При смене major версии Postgres следуйте официальной процедуре миграции, а не удалению тома.
